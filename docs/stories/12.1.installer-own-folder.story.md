### Context

Measured by the orchestrator on `9dafd44` (Epic 12, "Problem") and re-read by the SM:

- `!define INSTALLDIR "$PROGRAMFILES\${APPNAME}"` (l.17), `InstallDir "${INSTALLDIR}"` (l.27), `InstallDirRegKey HKLM "Software\${APPNAME}" "InstallDir"` (l.28). An upgrade reuses the previous folder. « Parcourir » appends « GDPR Pseudonymizer » to the folder chosen (NSIS §4.8.1.21). A folder typed by hand is used as typed.
- At install, `RMDir /r "$INSTDIR\_internal"` (l.109) runs before `File /r` (l.112), after the 2.3.2 check that the app and the command line are closed (l.84-100).
- At uninstall, `RMDir /r "$INSTDIR"` (l.158) deletes the whole folder; `RMDir /r "$SMPROGRAMS\${APPNAME}"` (l.161) the Start Menu folder.
- Risk (a): a typed folder such as `D:\Outils` is wiped entirely at uninstall, the user's own files included.
- Risk (b): a typed folder that already holds another PyInstaller app loses that app's `_internal` at install.
- The previous folder is saved at the end of the install section, `WriteRegStr HKLM "Software\${APPNAME}" "InstallDir" "$INSTDIR"` (l.138). On Lionel's machine it reads `C:\Program Files (x86)\GDPR Pseudonymizer` under `HKLM\Software\WOW6432Node\GDPR Pseudonymizer` (the 32-bit installer's registry view; `reg query`, read-only, 2026-11-18).
- The Windows installer has 25 downloads across 8 releases. No user report.

**What happens to the existing installs** (Epic 12, Lionel's third decision):
- Default folder or « Parcourir »: the folder already ends with « GDPR Pseudonymizer ». The new version upgrades in place and installs the new uninstaller. No message.
- Hand-typed folder (`D:\Outils`): the new version goes into `D:\Outils\GDPR Pseudonymizer`; nothing in `D:\Outils` is changed or deleted. At the end of the installation a message says where the new copy is, that the old copy is still in `D:\Outils` and can be deleted by hand, which files to delete, and not to run that folder's `Uninstall.exe` (the PM's addition: an NSIS uninstaller works on the folder it runs from, NSIS §4.2.2; the old one still runs `RMDir /r "$INSTDIR"` and would delete all of `D:\Outils`, the new subfolder included, plus the registry entries and shortcuts that now belong to the new copy).

**Known limitation (recorded in Epic 12, not fixed):** an install that is never upgraded keeps its old uninstaller, which still deletes its whole folder. The old copy left in a hand-typed folder keeps its old uninstaller too; the message covers that case. Whether it also goes to `docs/BACKLOG.md` as KL-012 is Lionel's call (question 3 below).

### Mechanism

Reference code follows. Its behaviour is the contract (the tests pin it); the dev may rename labels, not change the logic.

**1. The folder rule, one function used everywhere.**

- Why not `.onVerifyInstDir`: it only accepts or refuses the folder ("If this function calls Abort, the installation path in $INSTDIR is deemed invalid", NSIS §4.7.2.1.10). It cannot append the last part, and it runs on every edit of the field.
- Why not the page alone: a silent install shows no page, and `/D=` "sets the default installation directory ($INSTDIR), overriding InstallDir and InstallDirRegKey" (NSIS §3.2.1). So the rule also runs in `.onInit` ("called when the installer is nearly finished initializing", §4.7.2.1.2), where `$INSTDIR` already holds the `/D=` folder or the registry folder (§4.8.1.22: `InstallDirRegKey` "will override the InstallDir attribute if the registry key is valid"). The directory page then shows the final folder.
- The page: MUI2 "Page Custom Functions" (Modern UI 2 readme): "These defines should be set before inserting a page macro"; "the user input can be validated in the leave function". `$INSTDIR` holds the typed folder there; the function rewrites it.
- First in `SecMain`, as a safety net, so AC3 holds whatever set `$INSTDIR`.
- The check compares the last 19 characters, backslash included, with `\GDPR Pseudonymizer`: `StrCmp` "compares (case insensitively)" (§4.9.4.25); `StrCpy` with a negative start offset "will start abs(start_offset) from the end of the string", and a negative maxlen truncates from the end (§4.9.8.1). The backslash matters: with 18 characters, `D:\XGDPR Pseudonymizer` would pass. `${GetFileName}` (FileFunc, Appendix E.1.16) is not used: its handling of a trailing backslash is not documented.

```nsis
Var OldInstDir  ; the previous install's folder, read in .onInit (declare before the LangStrings)

; In: a folder on the stack. Out: the same folder without trailing backslashes.
Function TrimFolder
    Exch $0
    Push $1
    trim_loop:
    StrCpy $1 $0 1 -1
    StrCmp $1 "\" 0 trim_done
    StrCpy $0 $0 -1
    Goto trim_loop
    trim_done:
    Pop $1
    Exch $0
FunctionEnd

; In: a folder on the stack. Out: that folder, trimmed, ending in
; \GDPR Pseudonymizer (capitals ignored): the folder itself when it already
; ends so, otherwise its « GDPR Pseudonymizer » subfolder.
Function OwnFolderOf
    Call TrimFolder
    Exch $0
    Push $1
    Push $2
    StrLen $2 "\${APPNAME}"   ; 19
    IntOp $1 0 - $2           ; -19
    StrCpy $1 $0 $2 $1        ; the last 19 characters
    StrCmp $1 "\${APPNAME}" own_done
    StrCpy $0 "$0\${APPNAME}"
    own_done:
    Pop $2
    Pop $1
    Exch $0
FunctionEnd

Function .onInit
    ReadRegStr $OldInstDir HKLM "Software\${APPNAME}" "InstallDir"
    Push $INSTDIR
    Call OwnFolderOf
    Pop $INSTDIR
FunctionEnd

Function OwnFolderLeave
    Push $INSTDIR
    Call OwnFolderOf
    Pop $INSTDIR
FunctionEnd
```

Pages (l.49-54):

```nsis
!insertmacro MUI_PAGE_WELCOME
!insertmacro MUI_PAGE_LICENSE "..\..\LICENSE"
!define MUI_PAGE_CUSTOMFUNCTION_LEAVE OwnFolderLeave
!insertmacro MUI_PAGE_DIRECTORY
...
```

`SecMain`, first statements (before `check_app_closed:`):

```nsis
    SectionIn RO
    Push $INSTDIR
    Call OwnFolderOf
    Pop $INSTDIR
```

`StrCpy` gets an explicit maxlen (19) with the start offset (-19), so only documented semantics are used (an empty maxlen is a common idiom but not documented). A folder shorter than 19 characters cannot end with `\GDPR Pseudonymizer`, so it gets the subfolder whatever `StrCpy` returns for it. Labels are local to their function or section (§4.3), so `trim_loop` and `own_done` clash with nothing. Every register a function uses is pushed and popped, so `SecMain`'s `$0` (the `FileOpen` handle) is never clobbered (T1 checks it). A path `D:\` trims to `D:` and becomes `D:\GDPR Pseudonymizer`.

**2. The previous folder, read before it is written.** `ReadRegStr $OldInstDir HKLM "Software\${APPNAME}" "InstallDir"` in `.onInit`: same key and value as `InstallDirRegKey` (l.28) and `WriteRegStr` (l.138), which runs only at the end of `SecMain`. A missing value sets the error flag and an empty string (§4.9.2.12). Never take it from `$INSTDIR`: `/D=` and the folder rule have already changed it. The installer is 32-bit and adds no `SetRegView`, so it reads the same view it wrote (`WOW6432Node`, checked on Lionel's machine).

**3. The message, only in the typed-folder case, after the copy.** Last statement of `SecMain` (after `WriteRegStr ... "InstallDir" "$INSTDIR"`, so the message is true when shown and an aborted install never shows it):

```nsis
    Call OldCopyMessage
SectionEnd
```

```nsis
; After an upgrade from a folder typed by hand, the earlier copy stays where it
; was. Tell where both are, which files to delete by hand, and not to run the
; earlier Uninstall.exe: it would delete its whole folder (Story 12.1).
Function OldCopyMessage
    Push $0
    StrCmp $OldInstDir "" old_done
    Push $OldInstDir
    Call TrimFolder
    Pop $OldInstDir
    Push $OldInstDir
    Call OwnFolderOf
    Pop $0
    StrCmp $0 $OldInstDir old_done
    IfFileExists "$OldInstDir\gdpr-pseudonymizer.exe" 0 old_done
    MessageBox MB_OK|MB_ICONINFORMATION "$(MSG_OLD_COPY)" /SD IDOK
    old_done:
    Pop $0
FunctionEnd
```

- `StrCmp $0 $OldInstDir`: the folder rule leaves a trimmed folder unchanged exactly when it already ends in `\GDPR Pseudonymizer`, so equal means a default or « Parcourir » install: no message.

**4. The uninstaller, own files only.** In the uninstaller, `$INSTDIR` "contains the directory where the uninstaller lies" (§4.2.2), and the uninstaller runs from a temporary copy unless `_?=` is given (§3.2.2), so it can delete `Uninstall.exe`. `RMDir` without `/r` removes a folder "only if it is completely empty" (§4.9.1.9).

```nsis
Section "Uninstall"
    ; Remove only what the installer put there, then the folder if it is
    ; empty. Anything else in it stays (Story 12.1).
    Delete "$INSTDIR\gdpr-pseudonymizer.exe"
    Delete "$INSTDIR\gdpr-pseudo.exe"
    RMDir /r "$INSTDIR\_internal"
    Delete "$INSTDIR\Uninstall.exe"
    RMDir "$INSTDIR"

    Delete "$SMPROGRAMS\${APPNAME}\Uninstall.lnk"
```

### Test Plan

All in `tests/unit/test_windows_installer_script.py`, pure text and simulation: no NSIS, no Windows, no Qt, no spaCy; every CI leg runs them.

**New helpers** (new functions or a small class; the existing ones keep their behaviour):
- `_block(kind, name)`: the statements (token lists, as `_tokens` gives) of `Function <name>` ... `FunctionEnd` or `Section "<name>"` ... `SectionEnd`; raises `AssertionError` when absent.
- `_defines()`: the `!define` values (`APPNAME`, `INSTALLDIR`, ...), to expand `${...}` in strings.
- `_Nsis`: a small interpreter of the subset the installer uses, on one state: variables (`$INSTDIR`, `$0`-`$9`, `$R0`-`$R9`, declared `Var`s), a stack, a registry dict (`(root, key, value) -> str`), a file tree (a set of absolute paths, folders included), `silent`, and an event list. Strings expand `${NAME}` from `_defines()`, `$VAR`, `$\r$\n`; `$(MSG)` is kept as is.
  - Modelled: labels, `Goto`, `Push`, `Pop`, `Exch $x`, `Call` (into `_block("Function", ...)`), `StrCpy` (maxlen and start offset, negatives as §4.9.8.1; a negative offset beyond the start counts from the start), `StrLen`, `IntOp` (`+`, `-`), `StrCmp` (case-insensitive) and `StrCmpS` (case-sensitive, so a mutant is caught), `IfFileExists`, `ReadRegStr` (empty string when missing), `WriteRegStr` (into the dict), `MessageBox` (records `prompt <text token>`; in silent mode asserts `/SD` and takes its value; otherwise the `MB_OK` answer `IDOK`), `ClearErrors`/`FileOpen`/`IfErrors`/`FileClose` (as `_run`, nothing in use), `SetOutPath` (records the folder), `RMDir` (`/r`: removes the path and everything under it; without: removes it only if nothing is under it; records the event), `Delete` (records, removes), `File /r` (adds the three top-level items and a file under `_internal` to `$INSTDIR`, records `copy`), `WriteUninstaller` (adds it), `Abort` (stops).
