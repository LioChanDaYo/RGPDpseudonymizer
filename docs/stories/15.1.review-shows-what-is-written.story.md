**As a** user who reviews a document in the desktop app or the command line,
**I want** every row of the review list to say whether its pseudonym is written in the file, and the document to say, when I hover over a name, which pseudonym that text gets,
**so that** what I approve is what I get, and the mapping table holds only pseudonyms that were written.

**Priority:** the only story of Epic 15. It lands on `main` before Story 14.1, with a CHANGELOG `[Unreleased]` entry, and ships with the next release (none planned). No tag and no PyPI release without Lionel's go.

**Change type:** the review and the writing step only (`core/`, `gui/models/`, `gui/widgets/`, `validation/`, the desktop translations). No change to detection (`nlp/`, `resources/`), to any CLI flag, to the mapping-table schema or to a file format. What changes for the user:
- a row whose pseudonym is not written is marked, in the desktop list and in the command-line review;
- the review document's hover text shows (type, text, pseudonym, confidence, cell), and says, on a place whose pseudonym is not written there, which row's pseudonym is;
- the two names a partial overlap leaves partly in clear today are written in full;
- the mapping table stops saving pseudonyms that are never written.

### The mechanism: B (Lionel, 2026-11-22)

Both rows of an overlap stay in the review. A row whose pseudonym the end would not write, given the decisions taken, is marked. The end changes once, **E** (Dev Notes "Fix design", E): one function holds the writer's rule (`written_parts`, with the crossing rule for a partial overlap), the end resolves the overlaps before it draws, and a detection that is not written is neither drawn, saved nor counted.

#### H. The review document's hover text (Lionel's Q4)

Why it is never shown: `QTextEdit` answers a `ToolTip` event on its viewport with the character format at the pointer (`QWidgetTextControl`), and the editor's formats are only on `ExtraSelection`s (`entity_editor.py:281`, `:283-289`). So the editor answers the event itself.

1. **`_tooltip_block(entity_id: str, review: EntityReview) -> str`** (new): the text today built inline at `entity_editor.py:268-280`: type and text, `→` pseudonym, `qarg(self.tr("Confiance : %1"), …)`, and the cell line. `_apply_highlights` calls it for `fmt.setToolTip(...)`, which stays, so `test_entity_editor.py:67-75` is untouched and this story does not edit that file.
2. **`_apply_highlights` (`:206-307`)** also records `self._shown_ranges: list[tuple[int, int, str]]`: the (start, end, entity_id) of each selection it draws for a row. The navigation focus selection (`:291-305`) is not recorded. A row the hide toggles skip (`:223-234`) is not recorded either, so a hidden row is not described.
3. **`_char_at(point: QPoint) -> int | None`** (new): the character under the pointer, or None.
   - Take `c = self.cursorForPosition(point).position()`, the mapping a click uses (`:318`).
   - Then, among characters `c - 1` and `c`, return the one whose box holds the point. The box of character `k` runs from `cursorRect` at `k` to `cursorRect` at `k + 1`, on the same line.
   - For the last character of a visual line (a soft-wrapped line, or the line's end), `cursorRect` at `k + 1` is on the next line, so the box's right edge comes from the line itself (`QTextLine.cursorToX` of `k + 1` in its own line, or the line's natural width).
   - **The width, not the position, comes from the line** (PO, v1.3). `cursorToX` is in the block layout's coordinates, without the document margin or the scroll offset. So the box is `cursorRect(k).x()` plus `cursorToX(k + 1) − cursorToX(k)`, both in k's own line, from `cursorRect(k).top()` for the line's height. Then no margin or scroll arithmetic is needed. The PO's prototype (`po2_tip.py`, part 7) did this for every character. It mapped 270 of 270 points to the right character, or to none, in a 260-pixel editor of 54 soft-wrapped lines, scrolled. The points were the first and last character of each visual line, and blank space after each line's end. The 6 names broken across a wrap show their block on both lines.
   - A point in blank space after a line's end, or below the last line, holds no box and gives None (H3).
   - `cursorForPosition` alone is not enough: over the right half of a name's last letter it returns the end boundary, so no tooltip would show there (H1's second hover, M26).
4. **`viewportEvent(self, event: QEvent) -> bool`** (new override; `QAbstractScrollArea` routes the viewport's events through it).
   - On `QEvent.Type.ToolTip`, take `pos = self._char_at(event.pos())` and `ids = [eid for s, e, eid in self._shown_ranges if s <= pos < e]`. This is a scan of every range, not `_entity_at_position`'s bisection (`:324-338`), which returns one range and misses a second reading of the same text and a place inside an organisation name.
   - If `ids` is empty: `QToolTip.hideText()`, `event.ignore()`, return True.
   - Else: the blocks of `ids` in that order, joined by a blank line. ### Overfitting Check (for Codex findings and QA)

A finding counts only if both hold:
1. The real code fails that way on a realistic French document: two detections of a business or interview text overlap as the dev corpus's do (a same span of two types, a place inside an organisation name, a place with its preposition, a partial overlap).
2. A real user's steps reach it: desktop single or batch review (the list, or a hover over a highlighted place), command-line `process` or `batch` with review, a spreadsheet, with an ordinary database.

Invented overlaps no detector makes, other scripts, or a database edited by hand do not count.
