**I want** every row of the review list to say whether its pseudonym is written in the file, and the document to say, when I hover over a name, which pseudonym that text gets,

- a row whose pseudonym is not written is marked, in the desktop list and in the command-line review;
- the review document's hover text shows (type, text, pseudonym, confidence, cell), and says, on a place whose pseudonym is not written there, which row's pseudonym is;
- the two names a partial overlap leaves partly in clear today are written in full;
- the mapping table stops saving pseudonyms that are never written.

### The mechanism in detail (B)

- **The review state** computes, after each decision, which places of the list the end would receive are not written, and which row is written at each character (`written_parts`, the same function the end uses). It marks each row from that.
- **What the user sees (desktop list):** a row not written at any place shows N1 on its pseudonym line, between the arrow and the pseudonym; a row not written at some places shows N2 there. Placing the mark there makes it qualify the pseudonym, not the name (PO note), and keeps it visible when a long row is cut at the panel's edge (Exact texts).
- **What the user sees (desktop document):** hovering over a highlighted place shows its rows' lines (H); a row not written at that character gets N3, naming the row written there.
- **What the user sees (command line):** under `→ Pseudonym:` of a group the end would not write unless the groups that win are rejected, C1; for some places, C2. Example (i), the person group (persons are reviewed first, `workflow.py:392`): `→ Pseudonym:      Lilian Breton`, then `Written instead:  the pseudonym of Diego (LOCATION),` and, on the next line, `unless that group is rejected` (Exact texts).
- **Batch:** a row is one place, so N1 and N3 only.
- **A partial overlap (the crossing rule):** the crossing row is written over part of its place, so it is not marked. The hover text says which row is written over its first words.
- **Database and audit:** E.
- **Texts:** N1 to N3, C1, C2 (Exact texts).
- **Risks:**
  - a mark that lags a decision (G2 and G6 pin the update);
  - the command line's C1 is a condition, not a prediction, so it stays true whatever is decided later;
  - a hover text built before a decision (H reads its ranges from `_apply_highlights` and `writer_at` at the hover itself; H.6).

### Overfitting Check (for Codex findings and QA)

A finding counts only if both hold:
1. The real code fails that way on a realistic French document: two detections of a business or interview text overlap as the dev corpus's do (a same span of two types, a place inside an organisation name, a place with its preposition, a partial overlap).
2. A real user's steps reach it: desktop single or batch review (the list, or a hover over a highlighted place), command-line `process` or `batch` with review, a spreadsheet, with an ordinary database.

Invented overlaps no detector makes, other scripts, or a database edited by hand do not count.

**Writing the marked cases so they fail at an assert on the base (PO, v1.1; AC9):**
- **A missing interface is never a precondition.**
  - `pytest.fail("PRE: …")` raises `Failed`, not `AssertionError`, so a marked case that stops there is reported FAILED, not xfailed, under `raises=AssertionError`.
  - So the helpers return a value the first assert rejects. `_parts` returns None when `core/written_spans.py` or `written_parts` is absent, and W1's first line is `assert parts is not None  # expected failure`.
