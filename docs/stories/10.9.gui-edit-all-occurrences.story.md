## Story

**As a** desktop-app user correcting a detected name in the review list,
**I want** my edit to apply to every occurrence of that name and type, as it does in the CLI,
**so that** no other occurrence of the name is left in clear.

**Priority:** HIGH — it is a leak path: after an edit, the other occurrences of the name are not pseudonymized. It must land before the next release. It is not a 10.3c regression: the behaviour is in every desktop release since v2.0.0 (Story 6.8, PR #57), and the code is unchanged since v2.2.0.
**Change type:** desktop app review only. No detection change, so G1, G3 and G5 are N/A. No file under `gdpr_pseudonymizer/nlp/`, `gdpr_pseudonymizer/resources/`, `tests/accuracy/` or `tests/test_corpus/` changes. If any file the accuracy suite loads is touched, one regular accuracy run on the branch shows the 16 lines identical to `38212303870`.
**Ordering:** outside the detector chain. It goes after Story 10.8, because both change `gui/models/validation_state.py`, and never in the same PR as 10.8 (10.8 stays narrow: keys only).
**Epic:** [Epic 10: v2.3 — Detection Precision Quick Wins](../prd/epic-10-v2.3-detection-precision-quick-wins.md) (story 10.9)
**Branch:** `story/10.9-gui-edit-all-occurrences`, cut from `main` at `51d8429` (PR #95, Story 10.6 B15 close-out). It carries the PM's epic commit `ae7f308` (`docs/prd/` only: it adds Story 10.9). ### Context

At `main` `51d8429`:

### AC precisions (story-level)

- **AC1, "every occurrence of that name and type":** in single-document validation, every occurrence in the row's variant group: the variant-map entry of the row, looked up with the key Story 10.8 stores for the row at init. This includes other spellings that the grouping puts in the same row ("Dr Quentrel Zorbalia" and "Quentrel Zorbalia"; "Zorbalia" alone joins "Quentrel Zorbalia", P5b), as the CLI's groups do. In batch validation, where each occurrence is its own row, every row of the edited row's (text, type) group, the group accept and reject use since 10.8. The edited row is always included.
- **AC1, "each with its edited span":** the edited row keeps the span its caller passes; the edit dialog computes that span with the CLI's rule. Every other occurrence gets `ValidationWorkflow._locate_modified_span(document_text, occurrence, new_text)`, relative to its own detected span: the edited text where it overlaps that span, otherwise the detected span itself, with the edited text. No occurrence is ever dropped: where the edited text is absent, the place stays pseudonymized on its detected span, as in the CLI (T2).
- **AC1, the sent entity:** text is the edited text, type is the row's current type, and the other fields (confidence, gender, ambiguity flag, source, context label) come from the occurrence, as `get_validated_entities` builds the edited row today (`validation_state.py:296-308`).
- **AC1, "One undo reverts the whole edit":** in single-document validation the edit stays one `_ModifyTextCommand`; the other occurrences are derived from the row each time, so one undo reverts all of them and one redo re-applies them (T4). In batch validation the edit is one undo macro over the group's rows, the shape accept and reject use (`validation_state.py:129-134`) (T6).
- **AC1, highlights:** for an edited row, `get_all_entity_ranges` returns exactly the spans finalization sends (T5).
- **AC1 is checked at the output:** T1–T3 and T7 finalize and assert that no part of the invented name is left in the output.
- **AC2, the list:** the tests-first commit holds 7 tests that fail on the unfixed code (T1–T7) and 3 guard tests that pass on it (T8–T10); with Q1 "fold in", 9 that fail (T11–T12 added). The dev records both lists with their local outcomes (Task 1.2).
- **AC2, "Existing GUI and CLI validation tests stay green":** no existing test changes. On the SM's prototype, the existing GUI, document-processor and validation suites give the same result with and without the 10.9 change (Reproduction Evidence, item 11).
- **AC3, the wording:** Dev Notes "CHANGELOG Entry".

### Product Constraints (non-negotiable, verbatim from the epic)

### Fix Design (pre-decided)

1. **One span rule, the CLI's.** Every new span comes from `ValidationWorkflow._locate_modified_span(document_text, entity, new_text)` (`validation/workflow.py:431-458`), called as it is: a static method with no state. It returns the edited text's span that overlaps the entity's detected span, or the detected span when the text is not there. `validation/workflow.py` stays unchanged (epic Integration Points: "read only"). Import it inside the functions that use it, as `classify_known_entities` imports at `:103-106`, so loading the review model does not load the CLI's terminal UI (`readchar`, `rich`).

2. **Edit dialog** (`gui/screens/validation.py:577-592`): replace the search block `:578-589` with `new_start, new_end = ValidationWorkflow._locate_modified_span(doc_text, review.entity, text)`. The rest of the dialog does not change. Why: P5 (the old search can land on another occurrence) and the fallback, which could cover characters after the name. This is the CLI's rule for the edited row too.

3. **`modify_entity_text`** (`validation_state.py:155-164`): the rows are the edited row first, then every other row of its group from 10.8's group helper (the edited row is always included: for a row added by hand, 10.8's helper returns the detected rows of its text and type without the row itself).
   - One row: one `_ModifyTextCommand`, as today.
   - Several rows (batch validation): `beginMacro("Modifier le texte du groupe")`, one `_ModifyTextCommand` per row, `endMacro()`, the shape of `accept_entity` (`:129-134`). The edited row gets the span its caller passed; every other row gets `_locate_modified_span(document_text, row.entity, new_text)` on its own current span.
   - Every row of the group takes the edit whatever its state, as a group accept or reject does today.

4. **Private helper `_edited_occurrences(review, edited) -> list[DetectedEntity] | None`.** It looks up the row's stored 10.8 key in the variant map and returns `None` when the row has no stored key or the key has no entry (batch rows, rows added by hand). Otherwise, for each occurrence of the list, in order:
   - the occurrence that **is** `review.entity` (identity): `edited`, the entity `get_validated_entities` builds for the row (it already carries the row's edited span, moved in place by `_ModifyTextCommand`);
   - every other occurrence: a new `DetectedEntity` with `text=edited.text`, `entity_type=edited.entity_type` (the row's current type), the span from `_locate_modified_span(document_text, occurrence, edited.text)`, and `confidence`, `gender`, `is_ambiguous`, `source` and `context_label` from the occurrence.
   - If no occurrence is `review.entity` (not expected: the canonical is an element of its list, `entity_grouping.py:212`, and the session stores that object, `validation/models.py:179-188`), `edited` is put first, so the row is never lost.
   - It is computed on each call from the row's current `user_modification`, span and type. No new state: undo and redo of the one `_ModifyTextCommand` revert and re-apply every occurrence, and a later type change carries over.

5. **Private helper `_edited_entity(review) -> DetectedEntity`:** the construction at `:296-308`, moved out unchanged. 10.8's validated-rows helper and step 7 use it. `get_validated_entities` returns what it returns today.

6. **`expand_validated_entities`:** for each (row, entity) of 10.8's validated-rows helper, a row with `user_modification` sends `_edited_occurrences(row, entity)`, or `[entity]` when that is `None`. Every other row is unchanged from 10.8 (stored-key lookup; rows added by hand on the computed lookup). This replaces 10.8's text-edit exception. Docstring `:314-321`: a row whose text was edited expands to every occurrence of its group, each on its edited span or, where the edited text is absent, its detected span; ADDED rows stay single.

7. **`get_all_entity_ranges`:** a row with `user_modification` gives `(o.start_pos, o.end_pos, row id)` for each `o` of `_edited_occurrences(row, _edited_entity(row))`, or its own span when that is `None`. Every other row is unchanged from 10.8. The docstring says that an edited row's ranges are the spans finalization sends.

8. **Not changed:** `_ModifyTextCommand`, `_ChangePseudonymCommand`, `_AddEntityCommand`, the accept, reject and bulk actions, `classify_known_entities`, `get_validated_entities`' output, `gui/screens/batch.py`, the widgets, `detection_worker.py`, `document_processor.py`, every `nlp/` file, `validation/workflow.py`, `validation/models.py`, `data/`. `_ChangeTypeCommand` and `change_entity_type` stay unchanged unless Q1 is "fold in".

9. **Only with Q1 "fold in" (AC9):**
   - `change_entity_type`: the same rows as step 3; several rows give one macro of `_ChangeTypeCommand` ("Changer le type du groupe").
   - `expand_validated_entities`: a row without a text edit whose current type differs from its stored key's type sends every occurrence of its list with the row's type: `review.entity` as it is (already retyped), every other occurrence as a copy (`dataclasses.replace(occurrence, entity_type=row_type)`). The variant map itself is never changed.

Shape, for orientation only (the dev writes the real code):

```python
def _edited_occurrences(self, review, edited):
    key = self._candidate_key_by_id.get(review.entity_id)     # 10.8's stored key
    if key is None or key not in self._variant_occurrences:
        return None
    from gdpr_pseudonymizer.validation.workflow import ValidationWorkflow
    out = []
    for occ in self._variant_occurrences[key]:
        if occ is review.entity:
            out.append(edited)
            continue
        start, end = ValidationWorkflow._locate_modified_span(
            self._session.document_text, occ, edited.text)
        out.append(DetectedEntity(text=edited.text, entity_type=edited.entity_type,
                                  start_pos=start, end_pos=end, confidence=occ.confidence,
                                  gender=occ.gender, is_ambiguous=occ.is_ambiguous,
                                  source=occ.source, context_label=occ.context_label))
    return out if any(o is edited for o in out) else [edited, *out]
```
