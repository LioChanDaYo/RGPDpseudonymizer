### Lock check (AC5)

The raw `poetry.lock` diff (~425 lines) also carries expected churn that is **not** a movement: removed `markers = "python_version < \"3.11\""` dependency lines (exceptiongroup, tomli, typing-extensions entries under other packages), per-package `python-versions = ">=3.11"`, changed `[package.extras]` lists of fpdf2 and pillow, and the metadata `python-versions` and `content-hash`. The check is on package names and versions only. The dev saves this as `C:\Users\devea\Documents\GitHub\rgpd-analysis\r111\dev\lockdiff.py` (scratch, never committed) and runs it from the repo root with `poetry run python <path>`:

```python
import subprocess, tomllib
old = tomllib.loads(subprocess.run(["git", "show", "30de5f6:poetry.lock"], capture_output=True, encoding="utf-8", check=True).stdout)
new = tomllib.load(open("poetry.lock", "rb"))
o = {p["name"].lower(): p["version"] for p in old["package"]}
n = {p["name"].lower(): p["version"] for p in new["package"]}
for k in sorted(o.keys() | n.keys()):
    if o.get(k) != n.get(k):
        print(f"{k}: {o.get(k, '-')} -> {n.get(k, '-')}")
print("metadata python-versions:", old["metadata"]["python-versions"], "->", new["metadata"]["python-versions"])
```

`encoding="utf-8"` is required: `poetry.lock` holds non-ASCII text (l.1873, an emoji in a package description), and on Windows `text=True` alone decodes with cp1252, which fails on that emoji's bytes.
