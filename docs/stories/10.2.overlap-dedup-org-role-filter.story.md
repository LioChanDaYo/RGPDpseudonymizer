**As a** user reviewing detected entities,
**I want** one candidate per name instead of overlapping fragments, and no job titles offered as organisations,
**so that** I reject fewer false candidates during validation.

## Acceptance Criteria

AC2 to AC5 are copied from the epic (including the PO fixes now in it). AC1 is copied from the epic and extended with one sentence on GUIDELINES rule G7 (end of its last sub-bullet). AC6 to AC8 are story-level and come from the 10.2 drafting brief (2026-10-04).

1. **AC1 — Overlap rule defined in the story before coding.** The Dev Notes state the rule precisely (see "Same-Type Overlap Rule (AC1)"). Default rule, to be refined only with evidence from the main corpus:
   - Applies only to detections of the **same entity type** whose character spans overlap.
   - Spans are compared after app normalization, the same as the scorer's `_match_key` (`strip_french_titles` on all types, `strip_french_prepositions` on LOCATION), not after `_trim_entity_boundaries` (which only runs on spaCy entities).
   - If one span contains the other, keep the containing span.
   - If spans partially overlap and neither contains the other, keep the spaCy span; if both come from the same source, keep the longer span.
   - Ties are resolved deterministically (e.g. earliest start).
   - Overlaps between **different** types keep today's behaviour (both kept, logged); out of scope. Under the repaired ground truth a LOCATION nested inside an ORG is a legitimate pair (GUIDELINES rule G7), so a cross-type nested pair must never be deduplicated.
2. **AC2:** The rule is implemented in `HybridDetector`; the `partial_overlap` log is kept for the different-type case, and a distinct log event records same-type dedup decisions (kept span, dropped span, reason) without logging entity text beyond what the existing logs already do.
3. **AC3 — ORG role filter:** ORG detections whose whole normalized span is a job title or role acronym are dropped. The list lives in a resource file (not hard-coded), covers at least CEO, CTO, CFO, COO, CIO, CDO, DSI, DAF, DRH, DPO, RSSI, COMEX, CODIR, bare "VP", "VP/Vice-président + function" forms ("VP Engineering") and "VP/Vice-président + region/country" forms ("VP Europe", "VP France"), and is matched case-sensitively for acronyms. Real organisations that look like acronyms (CNIL, ANSSI, BNP, EY) are not in the list; a unit test proves they survive.
4. **AC4:** Unit tests for each rule branch (containment, partial overlap, same-source tie, different-type untouched, role drop, real-acronym kept).
5. **AC5 — Gates:** G1 (main and held-out lines), G2, G3 versus the 10.1 baseline, G4 (no annotation or scorer change in this PR), G5, G6 (plus NFR1 timing unchanged: existing perf test green), G7 per the Epic 10 G7 interpretation (Lionel, 2026-10-02): before/after recorded in the QA report in this story; README/README.fr, FAQ, docs index and tutorials are updated at Epic 10 close-out, not per story. CHANGELOG [Unreleased] entry describing the behaviour change, regardless of G7, including an upgrade note on pseudonym continuity (see Risk Mitigation). The story reports the measured FP reduction attributable to each of the two rules (one G1 run with both, plus the dedup-only or filter-only split if the dev runs it; every number cited with its run ID), and how many of the detections dropped by the overlap rule were TPs in the previous (10.1 close-out) run.
6. **AC6 — Re-measure F1/F2 before coding (story-level).** The epic's F1 (158 FP) and F2 (138 ORG FP) were sized against the old ground truth at `fceef65`. Before any detector code is written, the dev re-measures both against the current main-corpus annotations (2,215 entities), records the new sizes and the method in Dev Notes "Re-measured Sizes", and dry-runs the AC1 rule and the AC3 list on the baseline detections to predict the TPs each would drop. Main corpus only. The epic's arithmetic estimate (P ≈ 54.5%, F1 ≈ 63%) is void and is never cited.
7. **AC7 — Rules are generic (story-level).** The role list and the overlap rule are generic rules. They are never built from corpus FP lists alone: every role-list entry carries a justification that holds for any French business text (common French or English corporate role acronyms and titles). Each rule has unit tests on synthetic strings only, with clearly invented names (no corpus or held-out strings). Exemption: the `connectors` of the role resource ("de", "et", "&", …) are grammar words, not role entries, and need no `why`.
8. **AC8 — Held-out isolation (story-level, restates 10.1 AC5, 4.1, 5.5b, 6.6).** No agent working on this story (dev or QA) opens, lists, reads or greps anything under `tests/test_corpus/held_out/`. Held-out results are used only as the four aggregate `[HELD-OUT …]` lines of a CI `accuracy-results` artifact. Any change to `tests/unit/held_out_leakage_allowlist.json` needs Lionel's recorded approval in this story. See Dev Notes "Held-Out Isolation".

### Product Constraints (non-negotiable, verbatim from the epic)

[Source: prd/epic-10-v2.3-detection-precision-quick-wins.md#Product Constraints]

These apply to every story in this epic. A story that cannot meet its goal inside them stops and goes back to Lionel; it does not relax them.

1. **Local NLP only.** No LLM, no generative model, no API call, no cloud service, no telemetry. Every change is a deterministic rule, lexicon or pattern that runs offline.

6. **No public accuracy claim without CI evidence.** Every number that reaches README, FAQ, docs, CHANGELOG or the QA report comes from a cited CI accuracy run (gate G1).

### Code Map (read at draft time, `d4b7105`)

- **Pipeline** `HybridDetector.detect_entities` (`gdpr_pseudonymizer/nlp/hybrid_detector.py:81-134`): spaCy NER → `source="spacy"` → `_trim_entity_boundaries` (spaCy only, `:111`, method `:277-328`) → regex `match_entities` with the spaCy Doc → `source="regex"` → `_merge_entities` (`:125`).
- **Merge** `_merge_entities` (`:136-217`): starts from all spaCy entities; for each regex entity, scans spaCy entities and **breaks at the first overlap** (`:163-197`):
  - exact match (`_is_exact_match`, `:440-463`: same offsets **or** same `strip_french_titles` text, any type) → regex dropped, `duplicate_entity_removed` (`:167-174`);
  - Cabinet rule (`_should_prefer_regex_org`, `:219-252`: regex ORG with an org prefix containing a spaCy PERSON) → spaCy removed, regex kept (`:175-186`);
  - otherwise regex flagged `is_ambiguous=True`, both kept, `ambiguous_entity_added … reason="partial_overlap"` logged at debug with `regex_text`/`spacy_text` (`:187-197`). **This fires for same-type and different-type pairs alike.**
  - regex entity with no spaCy overlap → added, no check against other regex entities (`:199-201`).
  - then `_filter_title_only_entities` (`:208-209`, method `:330-364`, PERSON whose `strip_french_titles` text is empty) and `_filter_label_words` (`:211-212`, method `:366-407`, hard-coded label set), then sort by start (`:215`).
- **Regex layer** `RegexMatcher.match_entities` (`gdpr_pseudonymizer/nlp/regex_matcher.py:156-207`): every pattern category, name dictionary, geography dictionary; `_deduplicate_entities` (`:385-416`) removes only **identical spans** (keeps higher confidence, any type). So regex/regex same-type overlaps survive, e.g. `compound_names` "Jean-Luc" inside a `titles`/`full_names` "… Jean-Luc Moreau", or `location_indicators` "à Paris" around a geography "Paris" (`resources/detection_patterns.yaml`, `location_indicators` and `geography_dictionary` sections). spaCy `doc.ents` never overlap each other.
- **Existing ORG/role handling:** none. There is no role or job-title filter anywhere in `gdpr_pseudonymizer/`. The only ORG-specific logic is the Cabinet rule (`:219-252`) and the regex `organizations` patterns (`detection_patterns.yaml`). `_filter_label_words` is the closest pattern (hard-coded set; AC3 requires a resource file instead).

### Same-Type Overlap Rule (AC1)

The epic default, made precise. Task 2 freezes it; refinements only per Task 1.7 / STOP R.

**Definitions** (computed per detection `e`):
- `norm(e)`: `strip_french_titles(e.text)`; if `e.entity_type == "LOCATION"`, then `strip_french_prepositions(...)`. Same functions and order as `_match_key` and `DocumentProcessor._normalize_entity_text`. Use `gdpr_pseudonymizer.utils.french_patterns`, not `tests.accuracy`.
- `key(e)`: `norm(e)` lower-cased, whitespace collapsed (exactly `_match_key`).
- `core(e)`: the character span of `norm(e)` inside the raw span: `i = e.text.find(norm(e))`; if `i >= 0` and `norm(e)` is non-empty, `core = (e.start_pos + i, e.start_pos + i + len(norm(e)))`; otherwise (a title removed from the middle of the span) `core = (e.start_pos, e.end_pos)`. Same technique as `_compute_replacement_prefix`.
- Two detections **conflict** when they have the same `entity_type` and their raw spans overlap (`_has_overlap`, `:409-419`).

**Pairwise decision** for a conflicting pair (a, b), first rule that applies:
1. **Equal:** `core(a) == core(b)` or `key(a) == key(b)` → tie (go to 4).
2. **Containment:** `core(a)` contains `core(b)` (and they are not equal) → keep a. Applies whatever the sources.
3. **Partial overlap** (neither core contains the other):
   - sources differ → keep the spaCy one;
   - same source → keep the longer `core`; equal length → tie (go to 4).
4. **Tie-break (deterministic):** spaCy before regex; then longer raw span; then earliest `start_pos`; then the order in the merged list (stable).

Raw spans that overlap but whose cores do not (e.g. "Mme Dupont" next to a span that only touches the title) are not a conflict: rule 2/3 compare cores, and if cores are disjoint both are kept (log reason `cores_disjoint`). Cross-type pairs are never compared.

**Algorithm (default, deterministic):** sort all entities by `(start_pos, -end_pos, source != "spacy")`; walk them, keeping a `kept` list; for each new entity x, find every kept entity of the same type that conflicts with x; if x loses to any of them, drop x; otherwise remove every conflicting kept entity (x beat them all) and keep x. Each drop is logged. A different algorithm is acceptable only if it is deterministic, gives the same pairwise outcome on every 2-entity case, and the 3-entity chain test (Testing) documents its behaviour.

**Worked examples** (synthetic):
- spaCy PERSON "Jean-Luc" [0,8) + regex PERSON "Jean-Luc Martin" [0,15) → containment → keep regex "Jean-Luc Martin".
- regex LOCATION "à Lyon" [10,16) + regex LOCATION "Lyon" [12,16) → cores equal [12,16) → tie → both regex, longer raw span → keep "à Lyon" (mapping key "Lyon" either way; `_compute_replacement_prefix` keeps "à").
- spaCy PERSON "Marie Dubois" [0,12) + regex PERSON "Dubois, Jean" [6,18) → partial, different sources → keep spaCy.
- spaCy LOCATION "France" inside spaCy/regex ORG "Acme France" → different types → both kept (G7).

**Refinements** (only with main-corpus evidence; any change to a default branch needs Lionel's decision at STOP R):

- **C1 (candidate, PO validation 2026-10-04, not adopted until Lionel decides):** "containment keeps the containing span **unless** every token it adds outside the inner core has no uppercase letter and no digit; then the inner span wins." Tokens are the whitespace-delimited pieces of the outer core outside the inner core. Effect: "près de Lyon" vs "Lyon" (added tokens "près", "de": no uppercase, no digit) → "Lyon" wins; "Jean-Luc Martin" vs "Jean-Luc" ("Martin" has an uppercase letter) → the containing span still wins; "Paris 16ème" vs "Paris" ("16ème" has a digit) → the containing span still wins. Task 1.5 dry-runs the default and the default + C1; Lionel picks once at STOP R. If STOP R does not trigger, the default rule stands.

- **C2 (Task 1.7 proposal, dev, 2026-10-04, not adopted; Lionel decides at STOP R):** "containment keeps the containing span **unless** the outer core adds a line break (`\n`) outside the inner core; then the inner span wins." Generic reason: a name never runs across a line break in the app's input formats; a span that does is a boundary error of the detector (spaCy runs a name into the next line's heading). Evidence (main corpus, local dry-run): the largest containment-loss pattern (iv-a, 28 TPs) is exactly this; default + C2 is FN +47, C1 + C2 is FN +39. It still leaves a net recall loss in every type.
- **Equal-only (Task 1.7 proposal, dev, 2026-10-04, not adopted):** apply only rule 1 (equal cores or equal keys → tie-break) and keep both spans on containment and partial overlap (today's behaviour for those). Evidence: FP -61 from the dedup (PERSON -25, LOCATION -36), FN +5 (PERSON +1, LOCATION +4). Each of the 5 new FNs is a **cross-position scorer artefact**: two same-key detections at one place (e.g. "à <city>" and "<city>") were each matched to a same-text annotation, one of them at another place in the document where no detection exists; dropping the duplicate leaves that far annotation unmatched. No annotation loses the detection at its own position. Under strict G3 this still counts as a recall drop, so it also needs Lionel's sign-off.
- **Why the default loses recall (evidence for STOP R):** the containment branch assumes the longer span is the better one. On this detector the longer span is usually the boundary error: 64 of the default's dropped-TP→FN cases are an over-long outer span (line-break runs, trailing role words, run-on regex ORG clauses, spaCy LOCATION over an org-like name), and none is a C1 pattern (unstripped prefix 0). C1 recovers 8 of them.

#### Frozen rule text (Task 2.1, 2026-10-04; amended after STOP R the same day)

Frozen as the epic default, exactly as stated above under "Definitions", "Pairwise decision" (rules 1-4) and "Algorithm (default, deterministic)", with these precisions taken from the dry-run implementation (`scripts/accuracy_size_findings.py`, `decide()` / `dedup()`):
- **Conflict test:** same `entity_type`, raw spans overlap, and the pairwise decision does not return "keep both" (`cores_disjoint`). Cross-type pairs are never compared.
- **Rule order:** (1) equal cores or equal keys → tie; else cores disjoint → keep both; (2) containment → keep the outer core's entity; (3) partial overlap → spaCy if sources differ, else the longer core, equal length → tie; (4) tie-break: spaCy first, then the longer raw span, then the earlier `start_pos`, then the entity already kept (earlier in walk order).
- **Walk order:** `(start_pos, -end_pos, source != "spacy")`, stable. A new entity that loses to any kept rival is dropped; otherwise every conflicting kept rival is dropped and the new entity is kept. Output re-sorted by `start_pos`.
- **Refinements adopted at STOP R (Lionel, 2026-10-04): C1 and C2.** They amend only rule 2 (containment). For a containment pair, with `outer` the entity whose core contains the other's core and `inner` the other one, let `added` be the text of `outer.text` between `core(outer)` and `core(inner)` on each side (left piece + right piece, computed on the entity's own `text` with `start_pos` offsets, exactly as `core()`):
  - **C1:** if `added` splits on whitespace into at least one token and **every** token has no uppercase letter and no digit → `inner` wins, log reason `containment_inner_preferred`.
  - **C2 (as amended by Lionel's PR #81 review, 2026-10-04):** otherwise, if `added` contains a line break (`"\n"`): cut `outer` at the first line break of its span (document slice when the document text is available, else `outer.text`), trailing whitespace removed. If that trimmed span is non-empty and its core contains `core(inner)` → the **trimmed outer** replaces both (same type and source as `outer`), log reason `containment_outer_trimmed_linebreak`. Otherwise fall through to the default below. (Approved first version, superseded: `inner` wins, reason `containment_inner_preferred_linebreak`.)
  - otherwise `outer` wins, log reason `containment` (epic default).
  - C1 is checked before C2; both are checked only for containment (rule 2), never for equal (rule 1) or partial overlap (rule 3).
- **Rule 3 amended (Lionel, PR #81 review, 2026-10-04): partial overlap → union.** When the cores partially overlap (neither contains the other), both entities are replaced by one span from `min(start)` to `max(end)`. Its text is the document slice (else the left text plus the right text's tail), its type is unchanged, and its source is `"merged"`. The other fields are copied from the spaCy entity if there is one, and `is_ambiguous` is False. Log reason `partial_overlap_union`. This replaces "spaCy preferred, else longer core".
- **Walk with replacement:** when a pair resolves to a new span (union or trimmed outer), the kept rival is removed and the new span is compared again with every kept entity. Each replacement removes one entity, so the walk ends.
- **Coverage invariant (Lionel, PR #81 review):** the dedup never uncovers a name character, i.e. an upper-case letter or digit inside an input core. Two exceptions, by design: C1 drops only tokens without one, and the C2 trim drops what follows the first line break of an outer span whose trimmed core still contains the inner core. Unit-tested on random overlaps without line breaks.
- **Log reasons** for `same_type_overlap_resolved` (final): `containment`, `containment_inner_preferred` (C1), `containment_outer_trimmed_linebreak` (C2 as amended), `partial_overlap_union`, `tie`. A replacement logs one event per replaced input, with the new span as `kept_*` (`kept_source` `"merged"` for a union).
- **ORG segment trim, V3 (Lionel, 2026-10-04, after the ORG loss investigation):** for ORG pairs only, applied after the base decision above.
  - **Clause boundaries** in a span's text (the document slice when available): a line break; ",", ";" or ":" followed by whitespace; a period followed by whitespace and a non-space character. A period does not count after a word shorter than 3 letters, an all-caps word, or a title (Mme, Mlle, Prof, Dr, Pr, Me, M).
  - **Segment around an anchor:** the text between the last boundary ending at or before the anchor start and the first boundary starting at or after the anchor end, with whitespace stripped. No segment when the anchor itself crosses a boundary, when the segment would be the whole span, or when it is empty.
  - **Containment:** when the base decision keeps the outer span (`containment` or `containment_outer_trimmed_linebreak`), the segment of the original outer span around the inner core replaces both, provided the segment's core contains the inner core. Log reason `containment_outer_trimmed_boundary`.
  - **Union:** when the base decision is `partial_overlap_union`, the union is replaced by its segment around the overlap of the two cores, if there is one. Log reason `partial_overlap_union_trimmed`.
  - **Not PERSON** (a comma is part of "Last, First") and **not LOCATION**.
  - **Known gaps** (strict-xfail tests, handed to 10.3): a chain where an outer ORG first absorbs one contained name and is then cut to another name's segment; a union cut that drops a name held by one input. Neither occurs on the main corpus (0 new coverage loss).
- **Role filter keeps the place (Lionel, PR #81 review, 2026-10-04):** when a VP form is dropped, every place phrase it names (region phrases of the frozen `vp_regions` plus runtime `french_geography.json`; consecutive phrases joined only by de/du/des/d' form one place; function words, "et", "&" and "/" separate places) becomes a LOCATION detection. The span is located in the document slice of the ORG, else in its text, with whitespace-tolerant matching. Source and confidence come from the ORG. `org_role_filtered` gains `places_emitted` (a count, no text). "VP Engineering" and role acronyms emit nothing. No new place string is added to any resource.

### Known Risk: Unstripped LOCATION Prefixes

`location_indicators` (`detection_patterns.yaml`) matches `à|en|dans|près de|ville de` + capitalised words and returns the **whole match** (`regex_matcher.py:181-183` uses `match.group(0)`). `strip_french_prepositions` removes `à`/`en` but not `dans`, `près de` or `ville de`. Do not special-case these pairs outside C1.

### Where the Rules Plug In

Both rules go inside `_merge_entities`, after the existing post-filters and before the sort (`hybrid_detector.py:208-215`):

```
merge loop → _filter_title_only_entities → _filter_label_words → _filter_org_roles → _dedup_same_type_overlaps → sort
```

Rationale (judgment call):
- **Filters before dedup:** an entity that a filter would remove anyway (a role ORG, a title-only PERSON, a label word) must not win a containment contest and knock out a real entity first.
- **Inside `_merge_entities`:** that is where the existing post-filters live, and the existing unit tests call `_merge_entities` directly, so both rules are reachable in spaCy-free unit tests.
- **After `_trim_entity_boundaries`:** trimming already ran on spaCy entities; the dedup works on what the app will actually use. Normalization (titles/prepositions) is applied inside the comparison only; detections keep their raw text and offsets (no span rewriting in this story).
- **Merge loop:** keep the loop's decisions as they are; restrict both the `partial_overlap` log **and** the `is_ambiguous` flag to different-type pairs (Task 6.3). Same-type pairs are decided by the dedup pass.

User-visible effects to describe (plain language, no corpus or held-out strings; use invented examples such as "Jean-Luc" / "Jean-Luc Martin"):
1. **Fragments are no longer offered.** v2.2 showed both "Jean-Luc" and "Jean-Luc Martin" at the same place. If both were accepted, both got a mapping row, although the output text only used the longer one (`_apply_replacements` keeps the earliest, then longest span). From this version only "Jean-Luc Martin" is offered at that place, so no "Jean-Luc" row is created from it.
2. **Existing mapping databases keep working.** Rows created by v2.2 are still found by exact key, so an entity already mapped keeps its pseudonym.
3. **New databases can differ from old ones for short forms.** In a project started with this version, a later standalone "Jean-Luc" no longer finds a row created from an overlapping fragment; it is resolved by component matching (`_check_component_match`, PERSON only, `document_processor.py:345`) or gets a new pseudonym. A document processed with v2.2 and re-processed with a fresh database can therefore show a different pseudonym for such short forms.
4. **Partial overlaps now resolve to one combined span** (final behaviour, PR #81 review; updated for QA MNT-001). When two same-type spans partly overlap, v2.2's output kept the earlier-starting one and left the rest of the other unreplaced; this version offers one span covering both, so the whole covered text is replaced as one entity. Its mapping key is the combined text, which differs from the v2.2 key. A span crossing a line break may also be cut at the break. Users should check such spots during validation, as today.
5. **Role words are no longer pseudonymized as organisations.** "CTO", "DRH", "VP Europe" and the like are no longer offered as ORG. Rows a v2.2 database holds for them stay, but they are no longer applied, so these words now appear unchanged in the output (they are job titles, not personal data).
6. **Recommendation:** keep using the same mapping database across versions for consistent pseudonyms; re-process with v2.2 if byte-identical output with an old run is required.

### Code Quality Assessment

The implementation is clean and follows the frozen rule text.
- **Union.** The span runs from min(start) to max(end); its text is the document slice, with a fallback that splices the tail. Source is `merged`, and spaCy fields are copied.
- **C2 trim.** The span is cut at the first `\n`, `rstrip()` removes trailing whitespace, and `end_pos = start + len(kept)`.
- **CRLF/LF.** Documents are read with universal newlines (`file_handler.py:83`, `conftest` `read_text`). A QA probe on a `\r\n` document also trims correctly: "Zorbalia Quentin" [0,16), equal to the document slice.
- **Determinism.**
  - Tie-breaks: spaCy first, then the longer raw span, then the earlier start, then walk order.
  - Walk: sorted by `(start, -end, source != spacy)` with a stable sort.
  - Termination: each replacement removes one kept entity, so the walk ends.
- **Cross-type pairs.** They are skipped before any comparison (`hybrid_detector.py:814-819`), so a LOCATION nested in an ORG is never deduplicated. A test covers it.
- **`is_ambiguous`.** It is set only in the different-type branch of the merge loop (`:356-367`). The same-type branch appends the entity unflagged (`:368-372`), and a union forces `False`.
- **Role list.** It lives in YAML. All 20 acronyms, 5 prefixes, 73 functions and 23 regions have a non-empty `why`. It holds no region acronym, and none of CNIL, ANSSI, BNP or EY.
- **Countries.** They are read at runtime from `french_geography.json` (`_load_geography_region_words`, `:72-78`), behind an `lru_cache`.
- **Emitted places.** They are typed LOCATION and go through the dedup. Offsets are correct in the tested cases, with one edge case (REL-001).
- **Logs.** No new log event carries entity text.
