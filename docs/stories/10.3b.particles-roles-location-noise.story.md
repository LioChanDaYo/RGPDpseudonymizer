## Acceptance Criteria

AC1 to AC9 are copied from the epic's story 10.3b word for word: AC1–AC7 are the original 10.3 ACs, AC8 is the original text with its baseline amended at the split (Lionel, 2026-10-06), and AC9 was added by the split. Precisions are added in brackets, each marked *[story]*. AC10 to AC13 are story-level. Mapping to the combined 10.3 draft: AC1–AC8 unchanged, AC9 ← 11 (f), AC10 ← 9, AC11 ← 10, AC12 ← 14, AC13 ← 15. The former 11 (a–e), 12 (REL-004) and 13 (carried losses) were 10.3a's AC1–AC5 and AC7.

1. **AC1 — All-caps common words:** an all-caps LOCATION detection is dropped only on positive evidence that it is a common word (hit in a common-word stoplist / lexical check, e.g. "CONFORME", "CC"), never merely because it is absent from `french_geography.json`. All-caps real places survive: unit tests prove it for a dictionary place ("PARIS" in a header) and for foreign places not in the dictionary ("TOKYO", "BOSTON"). "US"/"USA" handling follows the approved guidelines from 10.1. *[story: under GUIDELINES Q14 and A5, "US", "USA", "UK", "UE" and "EU" are always LOCATION, so they are never in the stoplist. Under A8, region acronyms are LOCATION, so none is in the stoplist either. Held-out-blind tests (AC12): the foreign-place tests use "BOSTON" (it occurs in the main-corpus text) and the invented "ZORBAVILLE". "TOKYO" does not occur in the main-corpus text, so it is **not** used in tests unless Lionel approves it; this replaces the epic's "TOKYO" example in the tests only. "PARIS" occurs in the main-corpus text (case-insensitive token match, as the guard compares).]*
2. **AC2 — Common-noun false places:** LOCATION detections that are French common nouns or domain jargon and not in the geography dictionary ("Équipe", "Constat", "SecNumCloud", "Pentest") are dropped. The mechanism (stoplist resource, lexical check, or both) is chosen and documented in the story; it is deterministic and local. *[story: see Dev Notes "LOCATION Noise Rules": the default is a stoplist resource; a lexical check is a STOP R candidate.]*
3. **AC3 — Company names tagged as places:** a LOCATION detection that is not in the geography dictionary and matches a known organisation (e.g. "Wavestone") is retyped to ORG or dropped; the story states which and why. The known-organisation lexicon must come from a source independent of the test corpus, documented in the story (source, licence, date); held-out FP/FN lists are never used to build it. If no such independent source is available, AC3 is limited to dropping (no retype). Fragments such as "à Dr" are dropped. *[story: the lexicon is never retyped by hand from corpus strings. Without an independent source that Lionel approves at STOP R, the default is drop, never retype; Lionel may instead choose "retype on in-document evidence (i)", which uses no lexicon. "Wavestone" is one of the three ORG annotations that 10.3a left covered by a LOCATION span only (signed off at 10.3a STOP R), so a drop there is a level-2b case (Cross-Story Rules). See Dev Notes "Company-as-Place (AC3)".]*
4. **AC4 — Particles:** PERSON spans are extended to include surname particles (le, la, de, du, des, d', van, van der, von, and others listed in the story) when the particle is followed by a capitalised surname ("Jean-Charles Le Goff", "Sylvie van der Werf", "Chasseloup de Laubat"). *[story: the GUIDELINES negatives apply. de/du + ORG is not a particle (P4), and de + place is not a particle (Q12). See Dev Notes "Name Boundary Rules".]*
5. **AC5 — Mc/Mac:** names starting with "Mc"/"Mac" followed by a capital are not truncated ("Mme Sarah McAllister" → PERSON "Sarah McAllister" after title stripping).
6. **AC6 — Trailing roles:** a trailing ", Role" (e.g. ", Responsable", ", Directeur …") is trimmed from PERSON spans. *[story: a genuine "Last, First" ("Dubois, Jean-Marc", GUIDELINES Q2) is never trimmed.]*
7. **AC7:** Unit tests for every rule, including the negative cases (real all-caps places, a particle not followed by a surname, "Mac" as an ordinary word).
8. **AC8 — Gates (amended at split, Lionel 2026-10-06):** G1 (main and held-out), G2, G3 versus the previous merged baseline (10.3a close-out) (LOCATION recall is the type most at risk: report it explicitly), G4, G5, G6 (plus NFR1 timing unchanged: existing perf test green), G7 per the Epic 10 G7 interpretation (Lionel, 2026-10-02): before/after recorded in the QA report in this story; README/README.fr, FAQ, docs index and tutorials are updated at Epic 10 close-out, not per story. CHANGELOG [Unreleased] entry describing the behaviour change, regardless of G7, including an upgrade note on pseudonym continuity (see Risk Mitigation). *[story: the previous merged baseline is the 10.3a close-out run `37459114468` (reproduced on `main` by `37480506234` and `37534939934`). G3 is **strict**: any per-type FN increase in a G1 run versus it (FN ≤ 458 overall, 50 PERSON, 54 LOCATION, 354 ORG), unless Lionel sets per-type bounds at STOP R, stops the work and goes to Lionel (STOP G3). Before any coding, a dry-run projection is presented at STOP R. NFR1 is measured by a **real** `performance.yaml` run on the branch; its "Verify benchmark results are non-empty" step must pass, and every timing comparison names the runner CPU from pytest-benchmark `machine_info`.]*
9. **AC9 — " - Lead <Org>" variant (added by the split, 2026-10-06):** the AC6 trailing-role trim also covers a name followed by " - " and a role word on the same line ("<Name> - Lead <Org>", from the 10.2 handoff). Only the role word(s) are cut. The span becomes "<Name>" only if every capitalised word after the role word(s) is covered by another kept span; otherwise the span is not trimmed. Unit tests cover both branches. *[story: two more same-line shapes from the 10.2 handoff are STOP R candidates, decided by Lionel with the AC6 exception: a trailing role acronym with no comma ("<Name> DRH", GUIDELINES P6) and glued trailing punctuation ("<Name>):"). The " - Lead <Org>" variant and these candidates are part of the AC6 coverage exception Lionel signs off (AC11).]*
10. **AC10 — Re-measure and dry-run before coding, on post-10.3a code (story-level).** The epic's F6 (LOCATION noise) and F7 (name boundaries) were sized at `fceef65` on the old ground truth and are stale; 10.3a has since changed the spans. Before any product code is written, the dev:

1. **Local NLP only.** No LLM, no generative model, no API call, no cloud service, no telemetry. Every change is a deterministic rule, lexicon or pattern that runs offline.
2. **No encoder NER models.** Introducing a transformer/encoder NER model (e.g. CamemBERT-NER) is a Lionel decision that belongs to Epic 9. It must not be introduced in this epic, including as an optional dependency or experiment committed to the repo.
3. **Mandatory human validation stays.** No auto-accept mode, no `--no-validate`, no confidence-based skipping. Precision gains reduce the reviewer's workload; they do not replace the reviewer.
4. **No user data** for training, tuning or evaluation. All corpus and held-out documents are synthetic.
5. **Recall over precision.** Missing a real person is worse than showing an extra candidate. Any drop in overall recall or in any per-type recall needs Lionel's sign-off (gate G3).
6. **No public accuracy claim without CI evidence.** Every number that reaches README, FAQ, docs, CHANGELOG or the QA report comes from a cited CI accuracy run (gate G1).

### Dry-Run Protocol (lessons from 10.2 and 10.3a)

- **Reproduce first.** No dry-run number is trusted until the baseline dump reproduces the 10.3a close-out run exactly (1.1), and the re-merge of the pre-merge lists reproduces the dump (1.2).
- **Net, not gross.** `match_entities` (`tests/accuracy/conftest.py`) is exact text + type, one-to-one, with position only as a tiebreaker. A boundary fix can therefore show up as a TP gain, as a TP loss elsewhere, or as nothing. Re-score the **whole** post-rule dump and report the per-type net delta. STOP R and STOP G3 use the net delta.
- **Classify every lost TP:**
  - **position loss**: no detection now matches that annotation at its position, so it becomes an FN;
  - **taken over**: another detection now matches it;
  - **cross-position scorer artefact**: the lost TP was matching a same-text annotation elsewhere.
  Gained TPs are classified the same way (real fix vs artefact). 10.2 example: "AutoMotive SA" was kept clean at its position and still counted as a miss through re-pairing.
- **Coverage table** for every rule and composition: for each annotation that becomes a miss, is it still covered by a same-type span, covered by another type only, or uncovered? Also list every annotation that was fully covered by its own type in the baseline and no longer is (AC11 level 2), and every annotation of any type that loses its last cover of any type (level 2b).
- **Scripts:** start from `scripts/accuracy_runon_dryrun.py` (10.3a: pre-merge lists, in-script rule patches, re-merge, net delta, lost/gained TP classification, coverage levels 1/2/2b). Also available: `scripts/accuracy_dump_detections.py` (dump; `--record-dedup` records dedup drops), `scripts/accuracy_size_findings.py` (scoring, coverage, `VARIANTS`), `scripts/accuracy_org_loss_attribution.py` (attribution of new misses to rules), `scripts/accuracy_segment_trim_dryrun.py` (in-script patching pattern) and `scripts/accuracy_heldout_blind_check.py` (AC12 string check). New scripts are named `scripts/accuracy_*.py`, use `Path(__file__).resolve().parent.parent`, and call `_load_corpus_documents()` only. Dumps and outputs are written outside the repo and are never committed. Run them via `cmd.exe` + `poetry run python`.
- **Pipeline order matters.** Dry-run each rule at the point where it will plug in (below): before the merge (`_fix_person_boundaries`), in the first filter pass and in the post-split re-run (`_filter_location_noise`), inside the dedup (C2). 10.3a's drafted R-SPLIT placement lost recall in the dry-run and the late placement won; test the placement, not only the rule.
- **Fire count on non-targets.** 10.3a's first W-JOIN dry-run fired once on a label line, not a wrap; the dev stopped and the follower set was tightened. Report every firing of a new rule on a shape it was not meant for, even when the net delta is zero.

### Coverage Invariant (AC11)

Two levels from 10.2 (Lionel, PR #81 review, 2026-10-04; DOC-005 wording, 2026-10-06), plus level 2b (PO validation, 2026-10-06; now an epic Cross-Story Rule).

1. **Span level (rules that reshape spans: particles, Mc/Mac, trailing-role trim, dedup).** No rule may uncover a name character that a span of the same type covered before. A name character is an upper-case letter or a digit inside an input core. Same-type coverage after the rule must include every such character a same-type span covered before, unless an exception below applies.
   - **Existing exceptions (10.2):** C1 (dropped tokens have no upper-case letter and no digit); the C2 trim after the first line break when the trimmed core still contains the inner core (under review, QA REL-002); the guarded V3 cut (titles excepted; **no sentence-start exception since 10.3a**, REL-004 option (b)).
   - **10.3a exceptions (signed off, 10.3a decision 5):** run-on spans no longer produced by R-LB/R-ORG; label and role filters applied to R-SPLIT pieces. They carry over.
   - **Candidate exception, needs Lionel's sign-off at STOP R:** the AC6 trailing-role trim, which drops a capitalised role word (", Responsable"), and its AC9 variants ("<Name> DRH"; "<Name> - Lead <Org>", where only the role word(s) are cut and any further capitalised word must be covered by another kept span, else no trim). They are intended by the epic, but under this invariant they are an exception and must be signed off with the frozen role-word list.
   - **Regex pattern changes (Task 3.3: the `titles` Mc/Mac token shape; Task 6.0 if R-KWC is adopted)** never produce the old span at all. They are judged at level 2/2b and through the dry-run's span comparison: list every baseline regex span whose same-type characters are no longer covered by any span.
   - **C2 removal (QA REL-002):** removing C2 can only keep more of an outer span, and R-SPLIT late then keeps every line piece with a capital or digit, so it cannot uncover a same-type character. The Task 1.7 dry-run still reports levels 1/2/2b, because a kept outer span changes which span wins the dedup.
2. **Annotation level (every rule, filters included).** No main-corpus annotation may lose full coverage by spans of its own type versus the baseline dump. A filter that drops a LOCATION (AC1–AC3) or retypes it must show 0 newly uncovered LOCATION annotations; a retype must show 0 newly uncovered for both types. Any exception needs Lionel's recorded sign-off.
   - **2b. Last cover of any type (epic Cross-Story Rules, Lionel 2026-10-06).** Report every main-corpus annotation, of **any** type, that loses its **last** covering span of **any** type versus the baseline dump, i.e. it was covered by some detection (whatever its type) and is now covered by none. Example: ORG "Wavestone", covered today only by a LOCATION span that AC3 would drop. Each case needs Lionel's recorded sign-off. 2b catches the leaks that level 2 misses, because level 2 only looks at same-type cover.

Report levels 1, 2 and 2b at STOP R and at close-out. The coverage table gets a 2b column: "loses its last cover of any type" (count + list). The starting debt (Dev Notes "Baseline": 3 level-2 ORG, "Pierre" and "BRS") does not count as new.

### Name Boundary Rules (AC4, AC5, AC6)

Applied by `_fix_person_boundaries(entities, text, blockers)` to PERSON entities of both sources before the merge (Task 3.2). Only the Mc/Mac token shape is also mirrored in a regex pattern, the YAML `titles` (Task 3.3); particles are not. `blockers` = the pre-merge ORG and LOCATION spans of **both** sources (PO validation, 2026-10-06), so condition 4 is applied in full.

- **Particles (AC4).** The list is held in a resource (Task 3.1):
  - lower-case particles: le, la, de, du, des, d', van, van der, van den, von, der, den, ter, ten;
  - capitalised forms: Le, La, De, Du, Des, Van, Van Der, Van Den, Von, Di, Da, Del, Della, Dos;
  - the final list is frozen in Task 2, each entry with its `why`; entries that do not occur in the main-corpus text need Lionel's approval (AC12).

  A PERSON span is extended to the right over `particle(s) + one capitalised surname token` (hyphenated allowed: "de Laubat", "van der Werf", "Le Goff") when all of these hold:
  1. the particle chain starts right after the span, joined by single `HSPACE` characters only, on the same line. The elided particle **d'** (and **l'** where it is part of a particle chain) is glued to the next token, with no space, straight apostrophe `'` or typographic `’`: "Giscard d'Estaing" → the surname token is "Estaing", the particle "d'" has no space after it. A glued "d'X" counts as particle + capitalised token. It is subject to conditions 2–4 like any other particle ("Cour d'Appel de Paris" is an ORG: condition 4 or 2 stops it);
  2. exactly one capitalised token follows the chain, and it is **not** followed by another capitalised token. A run such as "de la French Tech Lyon" or "de Sorbonne Université" is an ORG or place name (P4 negative, Q3), not a surname;
  3. **all-caps tokens (PO validation, 2026-10-06; decided by Lionel at STOP R):** after a capitalised particle (Le, La, Van, Von, De, Du, …) or an all-caps particle (LE, LA, VAN, …), an all-caps surname token is allowed ("Jean LE QUENTRIX", the all-caps surname convention of French documents). After lower-case de/du/des/d', an all-caps token is **not** a surname: it marks an acronym ORG ("du CNRS"), so no extension. Task 1.4 counts all-caps surnames in the main corpus, and STOP R presents the count with this rule;
  4. it is not covered by an ORG or LOCATION detection (`blockers`), and it is not a geography-dictionary entry (case-folded) (P4 negative: de + ORG; Q12: de + place);
  5. for lower-case de/du/des/d', the dry-run must show that rule 4 is enough on the main corpus. Otherwise, propose a narrower rule at STOP R (e.g. extend lower-case de/du only when the span already ends in a known first name + surname pattern).

  A span that already **ends** in a particle ("Jean-Charles Le", the `titles` truncation) is extended by the next capitalised token under the same conditions. A particle not followed by a capitalised token is never added ("Zorbalia de la séance" stays "Zorbalia"). A particle at the end of a line, with the surname on the next line, is W-JOIN's case, not this rule's.
- **Mc/Mac (AC5).** A token `Mc[A-Z]…` or `Mac[A-Z]…` is one surname token, both in the YAML `titles` pattern (`detection_patterns.yaml:15`, Task 3.3) and in the extension step (`full_names` is unchanged). A span ending in a bare "Mc"/"Mac" that is directly followed by an upper-case letter in the text is extended to the end of that word. "Mac" as an ordinary word ("un Mac", not preceded by a name or title) is not a PERSON trigger.
  - Inner capitals in general ("LeCun", "O'Connor", Q11) are reported in 1.4 only. Extending them is not in the ACs and needs Lionel at STOP R.
- **Trailing roles (AC6).** A PERSON span whose text contains ", " followed by a role word from the frozen role-word list is cut before the comma ("Zorbalia Quentrel, Responsable technique" → "Zorbalia Quentrel"). Never when the word after the comma is a known first name (`NameDictionary.is_first_name`), the Q2 "Last, First" form; the role-word list must not contain first names (unit test).
  - The role-word list holds generic French/English job-title head words (Responsable, Directeur, Directrice, Chef, Président, Présidente, Gérant, Gérante, Associé, Associée, Consultant, Consultante, Ingénieur, Ingénieure, Manager, Head, Lead, Architecte, Développeur, Analyste, Avocat, Avocate, Juriste, Chargé, Chargée, Délégué, Déléguée, Secrétaire, Trésorier, …). The `org_role_filter.yaml` `acronyms` are reused by reference, never retyped.
  - **AC9 and its story extensions (dry-run, Lionel at STOP R):**
    - " - " + role word ("<Name> - Lead <Org>", AC9). **Cut only the role word(s)** after " - ", never the whole tail by default: the span becomes "<Name>" only if every capitalised word beyond the role word(s) (e.g. "<Org>") is covered by another kept span (any detection that survives the merge). Otherwise the span is **not trimmed** (10.2 precise-guard logic, PO validation 2026-10-06). This variant is part of the AC6 exception Lionel signs off (Coverage Invariant);
    - a trailing role acronym from `org_role_filter.yaml` with no comma ("<Name> DRH", GUIDELINES P6);
    - glued trailing punctuation on the last token ("<Name>):"): trailing `)`, `:`, `,`, `;` stripped from PERSON spans.
- **Keys after PR #86:** the mapping key is the stripped text with every whitespace run collapsed to one space (`document_processor.py:232`). A particle extension adds a word to the key; a trailing-role trim removes one. Spacing does not matter: "Le Quentrix" joined by a no-break space and by a plain space give the same key, so the dry-run and the continuity note reason on single-space keys.
- **Resource schema** (YAML, `yaml.safe_load`, like `org_role_filter.yaml`): `particles: [{term, why}]`, `role_words: [{term, why}]`, plus a header comment as in `org_role_filter.yaml` ("never add an entry because it appeared as an FP in the corpus alone; never add held-out strings").

### LOCATION Noise Rules (AC1, AC2, fragment part of AC3)

- **Mechanism (AC2 asks the story to choose): a stoplist resource** (`gdpr_pseudonymizer/resources/location_noise_filter.yaml`, `{term, why}` entries, compared case-folded and accent-sensitive). Reason: it is deterministic, reviewable and versioned, and each entry has a written justification (AC12).
  - Candidate refinement for STOP R: a lexical check using the installed spaCy model's own lexical data, e.g. `token.pos_ == "NOUN"` for a single-token LOCATION that is not a dictionary place. It is dry-run in Task 1 and adopted only by Lionel's decision, because POS on capitalised line-initial words is unreliable.
- **Entry categories** (each entry needs a `why` that holds for any French business text):
  - document status and label words used in all-caps headers and checklists (CONFORME, VALIDÉ, OK, CC, CCI, OBJET, URGENT, CONFIDENTIEL; the draft stoplist extras, not approved at STOP R, decision 5, are not named here);
  - French common nouns that start lines or headings (Équipe, Constat, Synthèse, Contexte, Annexe, Objectif, Recommandation, …);
  - security and IT jargon and certification names that are never places (Pentest, SecNumCloud (GUIDELINES Q6 b: a certification), Cloud, SOC, SIEM, …).
  - **Never in the list:** a place in `french_geography.json`; "US", "USA", "UK", "UE", "EU" (Q14/A5); compass regions "Nord", "Sud", "Est", "Ouest" (A3); region acronyms (A8). A unit test enforces this.
- **AC1 (all-caps):** an all-caps LOCATION (every letter upper-case, ≥ 2 letters) is dropped **only** if its case-folded normalized text is a stoplist entry. Absence from the dictionary is never a reason.
- **AC2 (mixed case):** a LOCATION whose normalized text is a stoplist entry and is not a dictionary place (case-folded) is dropped.
- **Fragment (AC3):** a LOCATION `t` is a fragment, and is dropped, when `strip_french_titles(strip_french_prepositions(t.text)) == ""`. Prepositions are stripped **first**: stripping titles first would leave "à" from "à Dr", which is not empty. It is also dropped when its normalized text is a bare preposition (the whole text matches one of `FRENCH_PREPOSITION_PATTERN`'s words: d', l', aux, au, des, du, de, à, en, compared case-insensitively). Examples: "à Dr", "à M" → dropped. Generic, no list. Unit tests: "à Dr" and "à M" dropped (both phrases occur in the main-corpus text); "à Zorbaville" kept.
- **Normalized text** here means the stoplist comparison text: `strip_french_titles`, then `strip_french_prepositions`, then whitespace collapsed, as the mapping key does since PR #86 (case-folded for the comparison only).
- Multi-word LOCATIONs are dropped only when the **whole** normalized text is an entry. A stoplist word inside a longer place ("Équipe Zorbaville") is not a hit. This is reported in 1.3 if it occurs.

### Pseudonym Continuity (CHANGELOG upgrade note, AC8)

The schema is unchanged. Since PR #86 the mapping key is the entity text with titles stripped (and prepositions, for places), then **every whitespace run collapsed to one space** (`DocumentProcessor._normalize_entity_text`, `core/document_processor.py:210-232`, no fallback). Boundary changes still change the key; spacing alone no longer does. The PR #86 CHANGELOG entry already covers the spacing change (names stored with unusual spacing get a new pseudonym once); 10.3b does not repeat it. [Source: prd/epic-10 "Risk Mitigation"] Describe, with invented examples only:
1. **Names are completed.** "Jean-Zorbal Le" becomes "Jean-Zorbal Le Quentrix", and "Sarah Mc" becomes "Sarah McZorbal". The new key differs from an older key for the truncated form. An existing database keeps its old rows, and the full name gets its own row (or is resolved by component matching for PERSON, `_check_component_match`, `document_processor.py:350`). Because keys are whitespace-collapsed, the completed name has one key whatever spaces join the particle (plain, no-break, narrow no-break).
2. **Trailing roles are no longer part of names** ("Zorbalia, Responsable" → "Zorbalia"). The key is the bare name, which an existing database may already hold; that row is found again, so the person keeps the pseudonym it already has.
3. **Common words and fragments are no longer offered as places** ("CONFORME", "à Dr"). Rows an older database holds for them stay, but are no longer applied.
4. **If AC3 retypes:** a company formerly offered as a place is offered as an organisation, with a different pseudonym category (the key text is the same, the entity type differs).
5. **If C2 is removed:** where a span ran over a line break, the text after the break is no longer dropped; it becomes its own candidate after R-SPLIT late, with its own key.
6. **Recommendation:** as in 10.2, keep the same mapping database across versions, and re-process with the old version if byte-identical output is required.
