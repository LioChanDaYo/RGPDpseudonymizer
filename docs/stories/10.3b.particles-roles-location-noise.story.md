## Story

**As a** user reviewing detected entities,
**I want** common words and company names not offered as places, and names with particles or "Mc/Mac" detected whole,
**so that** I reject fewer false places and do not have to repair cut names by hand.

**Priority:** MEDIUM (epic). Second half of epic story 10.3 (split by Lionel, 2026-10-06; see Dev Notes "Split Rationale"). **Starts only after story 10.3a is merged.**
**Change type:** Detector-only (G4). No annotation, scorer or held-out change in this story.
**Epic:** [Epic 10: v2.3 — Detection Precision Quick Wins](../prd/epic-10-v2.3-detection-precision-quick-wins.md) (story 10.3, split into 10.3a/10.3b)

## Acceptance Criteria

AC1 to AC9 are copied from the epic's story 10.3b (AC1–AC8 are the original 10.3 ACs word for word; AC9 was added by the split, PM update 2026-10-06). Precisions are added in brackets, each marked *[story]*. AC10 to AC13 are story-level. Mapping to the combined 10.3 draft: AC1–AC8 unchanged, AC9 ← 11 (f), AC10 ← 9, AC11 ← 10, AC12 ← 14, AC13 ← 15. The former 11 (a–e), 12 (REL-004) and 13 (carried losses) are in 10.3a (its AC1–AC5 and AC7).

1. **AC1 — All-caps common words:** an all-caps LOCATION detection is dropped only on positive evidence that it is a common word (hit in a common-word stoplist / lexical check, e.g. "CONFORME", "CC"), never merely because it is absent from `french_geography.json`. All-caps real places survive: unit tests prove it for a dictionary place ("PARIS" in a header) and for foreign places not in the dictionary ("TOKYO", "BOSTON"). "US"/"USA" handling follows the approved guidelines from 10.1. *[story: under GUIDELINES Q14 and A5, "US", "USA", "UK", "UE" and "EU" are always LOCATION, so they are never in the stoplist. Under A8, region acronyms are LOCATION, so none is in the stoplist either. Held-out-blind tests (AC14): the foreign-place tests use "BOSTON" (it occurs in the main-corpus text) and the invented "ZORBAVILLE". "TOKYO" does not occur in the main-corpus text, so it is **not** used in tests; this replaces the epic's "TOKYO" example in the tests only. "PARIS" occurs in the main-corpus text (case-insensitive token match, as the guard compares).]*
2. **AC2 — Common-noun false places:** LOCATION detections that are French common nouns or domain jargon and not in the geography dictionary ("Équipe", "Constat", "SecNumCloud", "Pentest") are dropped. The mechanism (stoplist resource, lexical check, or both) is chosen and documented in the story; it is deterministic and local. *[story: see Dev Notes "LOCATION Noise Rules": the default is a stoplist resource; a lexical check is a STOP R candidate.]*
3. **AC3 — Company names tagged as places:** a LOCATION detection that is not in the geography dictionary and matches a known organisation (e.g. "Wavestone") is retyped to ORG or dropped; the story states which and why. The known-organisation lexicon must come from a source independent of the test corpus, documented in the story (source, licence, date); held-out FP/FN lists are never used to build it. If no such independent source is available, AC3 is limited to dropping (no retype). Fragments such as "à Dr" are dropped. *[story: the lexicon is never retyped by hand from corpus strings. Without an independent source that Lionel approves at STOP R, the default is drop, never retype; Lionel may instead choose "retype on in-document evidence (i)", which uses no lexicon. See Dev Notes "Company-as-Place (AC3)".]*
4. **AC4 — Particles:** PERSON spans are extended to include surname particles (le, la, de, du, des, d', van, van der, von, and others listed in the story) when the particle is followed by a capitalised surname ("Jean-Charles Le Goff", "Sylvie van der Werf", "Chasseloup de Laubat"). *[story: the GUIDELINES negatives apply. de/du + ORG is not a particle (P4), and de + place is not a particle (Q12). See Dev Notes "Name Boundary Rules".]*
5. **AC5 — Mc/Mac:** names starting with "Mc"/"Mac" followed by a capital are not truncated ("Mme Sarah McAllister" → PERSON "Sarah McAllister" after title stripping).
6. **AC6 — Trailing roles:** a trailing ", Role" (e.g. ", Responsable", ", Directeur …") is trimmed from PERSON spans. *[story: a genuine "Last, First" ("Dubois, Jean-Marc", GUIDELINES Q2) is never trimmed.]*
7. **AC7:** Unit tests for every rule, including the negative cases (real all-caps places, a particle not followed by a surname, "Mac" as an ordinary word).
8. **AC8 — Gates:** G1 (main and held-out), G2, G3 versus the 10.2 baseline (LOCATION recall is the type most at risk: report it explicitly), G4, G5, G6 (plus NFR1 timing unchanged: existing perf test green), G7 per the Epic 10 G7 interpretation (Lionel, 2026-10-02): before/after recorded in the QA report in this story; README/README.fr, FAQ, docs index and tutorials are updated at Epic 10 close-out, not per story. CHANGELOG [Unreleased] entry describing the behaviour change, regardless of G7, including an upgrade note on pseudonym continuity (see Risk Mitigation). *[story: the baseline for 10.3b is the **merged 10.3a close-out run**, not run H and not the 10.2 baseline (Split Rationale). G3 is **strict**: any per-type FN increase in a G1 run versus the 10.3a close-out run (thresholds filled in at Task 0, Dev Notes "Baseline") stops the work and goes to Lionel (STOP G3). Before any coding, a dry-run projection is presented at STOP R. NFR1 is measured by a **real** `performance.yaml` run on the branch; its "Verify benchmark results are non-empty" step must pass, and every timing comparison names the runner CPU from pytest-benchmark `machine_info`.]*
9. **AC9 — " - Lead <Org>" variant (added by the split, 2026-10-06):** the AC6 trailing-role trim also covers a name followed by " - " and a role word on the same line ("<Name> - Lead <Org>", from the 10.2 handoff). Only the role word(s) are cut. The span becomes "<Name>" only if every capitalised word after the role word(s) is covered by another kept span; otherwise the span is not trimmed. Unit tests cover both branches. *[story: two more same-line shapes from the 10.2 handoff are STOP R candidates, decided by Lionel with the AC6 exception: a trailing role acronym with no comma ("<Name> DRH", GUIDELINES P6) and glued trailing punctuation ("<Name>):"). The " - Lead <Org>" variant and these candidates are part of the AC6 coverage exception Lionel signs off (AC11).]*
10. **AC10 — Re-measure and dry-run before coding, on post-10.3a code (story-level).** The epic's F6 (LOCATION noise) and F7 (name boundaries) were sized at `fceef65` on the old ground truth and are stale; 10.3a has since changed the spans. Before any product code is written, the dev:
    - re-measures F6 and F7 on the current main-corpus annotations, against a local dump of the **merged 10.3a code** that reproduces the 10.3a close-out run exactly;
    - dry-runs every candidate rule (AC1–AC6, AC9) on the main corpus, on post-10.3a code;
    - reports, for each rule and for the composed set, the **net** per-type FN/FP delta of the re-scored dump, the coverage table (levels 1, 2, 2b), and the classification of every lost TP (Dev Notes "Dry-Run Protocol").
    - The results go to Lionel at **STOP R**, which always fires in this story (Tasks).
11. **AC11 — Coverage invariant (story-level, from 10.2).** No rule may uncover a character that a span of the same type covered before (exact definition in Dev Notes "Coverage Invariant"). The only exceptions are those listed there, each with Lionel's recorded sign-off. In addition, no main-corpus annotation may lose full coverage, by spans of its own type, versus the baseline dump unless Lionel signs it off. Every annotation of any type that loses its last covering span of any type is reported and needs Lionel's sign-off (level 2b). Every dry-run and every close-out reports the coverage table.
12. **AC12 — Rules are generic (as 10.2 AC7).**
    - Every stoplist or lexicon entry carries a `why` that holds for any French business text. No entry is added only because it appears as an FP in the corpus.
    - External lexicons come from a documented source (name, licence, version/date) that is independent of the corpus.
    - Unit tests use synthetic strings with clearly invented names. They never use corpus or held-out strings, except the generic words the rules themselves name (role words, particles, stoplist words, and the place names AC1 names).
    - **Held-out-blind rule (PO validation, 2026-10-06):** Any real (non-invented) string in a new test or resource must occur in the main-corpus text (`tests/test_corpus/interview_transcripts/`, `business_documents/`), or be approved by Lionel before the guard runs. "Occur" means the case-insensitive whole-token match the leakage guard uses (`token_string`, `tests/unit/test_held_out_leakage.py`). The dev checks every real string mechanically against the main-corpus text before the guard first runs, and lists the strings that need approval at STOP R (Dev Notes "Held-Out Isolation" → "Strings that need Lionel's approval").
13. **AC13 — Held-out isolation (restates 10.1 AC5 and 10.2 AC8).** No agent working on this story (dev or QA) opens, lists, reads or greps anything under `tests/test_corpus/held_out/`. Held-out results are used only as the four aggregate `[HELD-OUT …]` lines of a CI `accuracy-results` artifact. Any change to `tests/unit/held_out_leakage_allowlist.json` needs Lionel's recorded approval in this story. See Dev Notes "Held-Out Isolation".

### Dry-Run Protocol (lessons from 10.2)

- **Reproduce first.** No dry-run number is trusted until the baseline dump reproduces the 10.3a close-out run exactly (1.1), and the re-merge of the pre-merge lists reproduces the dump (1.2).
- **Net, not gross.** `match_entities` (`tests/accuracy/conftest.py`) is exact text + type, one-to-one, with position only as a tiebreaker. A boundary fix can therefore show up as a TP gain, as a TP loss elsewhere, or as nothing. Re-score the **whole** post-rule dump and report the per-type net delta. STOP R and STOP G3 use the net delta.
- **Classify every lost TP:**
  - **position loss**: no detection now matches that annotation at its position, so it becomes an FN;
  - **taken over**: another detection now matches it;
  - **cross-position scorer artefact**: the lost TP was matching a same-text annotation elsewhere.
  Gained TPs are classified the same way (real fix vs artefact). 10.2 example: "AutoMotive SA" was kept clean at its position and still counted as a miss through re-pairing.
- **Coverage table** for every rule and composition: for each annotation that becomes a miss, is it still covered by a same-type span, covered by another type only, or uncovered? Also list every annotation that was fully covered by its own type in the baseline and no longer is (AC11 level 2), and every annotation of any type that loses its last cover of any type (level 2b).
- **Scripts:** use and extend `scripts/accuracy_dump_detections.py` (dump; `--record-dedup` records dedup drops), `scripts/accuracy_size_findings.py` (scoring, coverage, `VARIANTS`), `scripts/accuracy_org_loss_attribution.py` (attribution of new misses to rules), and `scripts/accuracy_segment_trim_dryrun.py` (V3-style in-script patching pattern). New scripts are named `scripts/accuracy_*.py`, use `Path(__file__).resolve().parent.parent`, and call `_load_corpus_documents()` only. Dumps and outputs are written outside the repo and are never committed. Run them via `cmd.exe` + `poetry run python`.
- **Pipeline order matters.** Dry-run each rule at the point where it will plug in (below), because filters before the dedup change which span wins a containment.

Why:
- **Fix spans at the source (10.3a; here Task 3.3).** 10.2 showed that over-long spans make the dedup's containment and union rules lose recall: 64 of the default rule's losses were over-long outer spans, and the 13 ORG run-on losses came from the `organizations` regex. Placing it before `_filter_org_roles` keeps the role filter's emitted places (frozen `vp_regions` + geography) out of the noise filter. ### Name Boundary Rules (AC4, AC5, AC6)

Applied by `_fix_person_boundaries(entities, text, blockers)` to PERSON entities of both sources before the merge (Task 3.2), and mirrored in the regex patterns (Task 3.3). `blockers` = the pre-merge ORG and LOCATION spans of **both** sources (PO validation, 2026-10-06), so condition 4 is applied in full.

- **Particles (AC4).** The list is held in a resource (Task 3.1 or a section of the role-word resource):
  - lower-case particles: le, la, de, du, des, d', van, van der, van den, von, der, den, ter, ten;
  - capitalised forms: Le, La, De, Du, Des, Van, Van Der, Van Den, Von, Di, Da, Del, Della, Dos;
  - the final list is frozen in Task 2, each entry with its `why`.

  A PERSON span is extended to the right over `particle(s) + one capitalised surname token` (hyphenated allowed: "de Laubat", "van der Werf", "Le Goff") when all of these hold:
  1. the particle chain starts right after the span (single horizontal spaces only, `HSPACE` below). The elided particle **d'** (and **l'** where it is part of a particle chain) is glued to the next token, with no space, straight apostrophe `'` or typographic `’`: "Giscard d'Estaing" → the surname token is "Estaing", the particle "d'" has no space after it. A glued "d'X" counts as particle + capitalised token. It is subject to conditions 2–4 like any other particle ("Cour d'Appel de Paris" is an ORG: condition 4 or 2 stops it);
  2. exactly one capitalised token follows the chain, and it is **not** followed by another capitalised token. A run such as "de la French Tech Lyon" or "de Sorbonne Université" is an ORG or place name (P4 negative, Q3), not a surname;
  3. **all-caps tokens (PO validation, 2026-10-06; decided by Lionel at STOP R):** after a capitalised particle (Le, La, Van, Von, De, Du, …) or an all-caps particle (LE, LA, VAN, …), an all-caps surname token is allowed ("Jean LE QUENTRIX", the all-caps surname convention of French documents). After lower-case de/du/des/d', an all-caps token is **not** a surname: it marks an acronym ORG ("du CNRS"), so no extension. Task 1.4 counts all-caps surnames in the main corpus, and STOP R presents the count with this rule;
  4. it is not covered by an ORG or LOCATION detection, and it is not a geography-dictionary entry (case-folded) (P4 negative: de + ORG; Q12: de + place);
  5. for lower-case de/du/des/d', the dry-run must show that rule 4 is enough on the main corpus. Otherwise, propose a narrower rule at STOP R (e.g. extend lower-case de/du only when the span already ends in a known first name + surname pattern).

  A span that already **ends** in a particle ("Jean-Charles Le", the regex truncation) is extended by the next capitalised token under the same conditions. A particle not followed by a capitalised token is never added ("Quentin de la réunion" stays "Quentin").
- **Mc/Mac (AC5).** A token `Mc[A-Z]…` or `Mac[A-Z]…` is one surname token, both in the regex patterns (`titles`, `full_names`) and in the extension step. A span ending in a bare "Mc"/"Mac" that is directly followed by an upper-case letter in the text is extended to the end of that word. "Mac" as an ordinary word ("un Mac", not preceded by a name or title) is not a PERSON trigger.
  - Inner capitals in general ("LeCun", "O'Connor", Q11) are reported in 1.4 only. Extending them is not in the ACs and needs Lionel at STOP R.
- **Trailing roles (AC6).** A PERSON span whose text contains ", " followed by a role word from the frozen role-word list is cut before the comma ("Catherine Zorbalia, Responsable sécurité" → "Catherine Zorbalia"). Never when the word after the comma is a known first name (`NameDictionary.is_first_name`), the Q2 "Last, First" form; the role-word list must not contain first names (unit test).
  - The role-word list holds generic French/English job-title head words (Responsable, Directeur, Directrice, Chef, Président, Présidente, Gérant, Gérante, Associé, Associée, Consultant, Consultante, Ingénieur, Ingénieure, Manager, Head, Lead, Architecte, Développeur, Analyste, Avocat, Avocate, Juriste, Chargé, Chargée, Délégué, Déléguée, Secrétaire, Trésorier, …). The `org_role_filter.yaml` `acronyms` are reused by reference, never retyped.
  - **AC9, story extension (dry-run, Lionel at STOP R):**
    - a trailing role acronym from `org_role_filter.yaml` with no comma ("<Name> DRH", GUIDELINES P6);
    - " - " + role word ("<Name> - Lead <Org>"). **Cut only the role word(s)** after " - ", never the whole tail by default: the span becomes "<Name>" only if every capitalised word beyond the role word(s) (e.g. "<Org>") is covered by another kept span (any detection that survives the merge). Otherwise the span is **not trimmed** (10.2 precise-guard logic, PO validation 2026-10-06). This variant is part of the AC6 exception Lionel signs off (Coverage Invariant);
    - glued trailing punctuation on the last token ("<Name>):"): trailing `)`, `:`, `,`, `;` stripped from PERSON spans.
- **Resource schema** (YAML, `yaml.safe_load`, like `org_role_filter.yaml`): `particles: [{term, why}]`, `role_words: [{term, why}]`, plus a header comment as in `org_role_filter.yaml` ("never add an entry because it appeared as an FP in the corpus alone; never add held-out strings").

### LOCATION Noise Rules (AC1, AC2, fragment part of AC3)

- **Mechanism (AC2 asks the story to choose): a stoplist resource** (`gdpr_pseudonymizer/resources/location_noise_filter.yaml`, `{term, why}` entries, compared case-folded and accent-sensitive). Reason: it is deterministic, reviewable and versioned, and each entry has a written justification (AC12).
  - Candidate refinement for STOP R: a lexical check using the installed spaCy model's own lexical data, e.g. `token.pos_ == "NOUN"` for a single-token LOCATION that is not a dictionary place. It is dry-run in Task 1 and adopted only by Lionel's decision, because POS on capitalised line-initial words is unreliable.
- **Entry categories** (each entry needs a `why` that holds for any French business text):
  - document status and label words used in all-caps headers and checklists (CONFORME, NON CONFORME, VALIDÉ, OK, NA, CC, CCI, PJ, OBJET, URGENT, CONFIDENTIEL);
  - French common nouns that start lines or headings (Équipe, Constat, Synthèse, Contexte, Annexe, Objectif, Recommandation, …);
  - security and IT jargon and certification names that are never places (Pentest, SecNumCloud (GUIDELINES Q6 b: a certification), Cloud, SOC, SIEM, …).
  - **Never in the list:** a place in `french_geography.json`; "US", "USA", "UK", "UE", "EU" (Q14/A5); compass regions "Nord", "Sud", "Est", "Ouest" (A3); region acronyms (A8). A unit test enforces this.
- **AC1 (all-caps):** an all-caps LOCATION (every letter upper-case, ≥ 2 letters) is dropped **only** if its case-folded normalized text is a stoplist entry. Absence from the dictionary is never a reason.
- **AC2 (mixed case):** a LOCATION whose normalized text is a stoplist entry and is not a dictionary place (case-folded) is dropped.
- **Fragment (AC3):** a LOCATION `t` is a fragment, and is dropped, when `strip_french_titles(strip_french_prepositions(t.text)) == ""`. Prepositions are stripped **first**: stripping titles first would leave "à" from "à Dr", which is not empty. It is also dropped when its normalized text is a bare preposition (the whole text matches one of `FRENCH_PREPOSITION_PATTERN`'s words: d', l', aux, au, des, du, de, à, en, compared case-insensitively). Examples: "à Dr", "en M" → dropped. Generic, no list. Unit tests: "à Dr" and "en M" dropped; "à Zorbaville" kept.
- Multi-word LOCATIONs are dropped only when the **whole** normalized text is an entry. A stoplist word inside a longer place ("Équipe Zorbaville") is not a hit. This is reported in 1.3 if it occurs.
