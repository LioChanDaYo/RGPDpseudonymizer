### AC precisions (story-level)

- **AC1, "keeps its cell":** every place a CLI decision rebuilds a name is a `dataclasses.replace` of the entity it changes: [T] (`ValidationSession.change_entity_type`, `validation/models.py:309-338`), [E] (`validation/workflow.py:291-304`) and the corrected-name fallback (`ValidationSession._sent_entity`, `validation/models.py:395-404`, unreachable from the CLI today because `mark_modified` always sets `modified_entity`, `:279`; T12 pins it). So `context_label`, `confidence`, `gender` and `source` are kept, and only what the decision changes is replaced. [E] then [T] and [C] after [E] follow, because [T] retypes the entity the review sends (10.11 AC11) and [C] sends it. "At every place of its group": every occurrence of the group is rebuilt the same way, each in its own cell. ### Fix Design (pre-decided; product rules as Lionel answered; texts per Q1 and Q2)

The SM prototype implements it (`proto_1015.diff`; Reproduction Evidence). The dev agent writes the real code from this text.

**AC1, the cell is kept (`validation/models.py`, `validation/workflow.py`).**
1. `ValidationSession.change_entity_type`: `self.mark_modified(entity, dataclasses.replace(sent, entity_type=new_type, is_ambiguous=False))`, `sent` as today (the correction, else the detected entity).
2. [E]: for each occurrence, `dataclasses.replace(entity, text=new_text, start_pos=start_pos, end_pos=end_pos, is_ambiguous=False)`, positions from AC2.
3. `ValidationSession._sent_entity`'s fallback: `dataclasses.replace(review.entity, text=review.user_modification)`.
4. Side effect, stated: [E] now keeps the detected entity's `source` (today it fell back to the default "spacy"). Nothing in the CLI path reads `source` after the review.

**AC2, a correction is found inside its cell (`validation/models.py`, `validation/workflow.py`, `core/document_processor.py`).**
1. `ValidationSession.cell_texts: dict[str, str] = field(default_factory=dict)` (cell reference → cell text; empty for a text document) and `text_of(entity) -> str`: the cell's text when `entity.context_label` is one of `cell_texts`, else `document_text`.
2. `ValidationWorkflow.run(…, cells: dict[str, str] | None = None)` fills `cell_texts` (the session `:96-99` and the manual flow's session `:621-624`) and passes `cells=cells` **by keyword** through both restarts (`:126-133`, `:144-151`) and to `_manual_entity_addition_flow(…, cells=cells)`; `run_validation_workflow(…, cells=None)` passes `cells=cells` to `run`. By keyword everywhere, as 10.13 passes `sent_without_review` on the same lines (Ordering and Rebase).
3. `DocumentProcessor._run_validation(…, cells=None)` passes `cells=cells` by keyword to `run_validation_workflow` (`None` for a text document; every existing fake takes keyword arguments, AC11). `_process_document_tabular` passes `{cell.cell_ref: cell.value for cell in tabular_doc.cells}`.
4. [E]: `self._locate_modified_span(session.text_of(entity), entity, new_text)`; `_locate_modified_span` itself does not change.

**AC3, [A] at every place (`validation/models.py`, `validation/workflow.py`).**

2. `ValidationSession.is_listed_place(place) -> bool`: some review's entity has the same text, type, start, end and `context_label` (a detected entity: AC14 (b), a found place; or an earlier added place).
3. `_handle_add_entity`: after the type check, `places = session.places_of(text, type)`; none → the existing warning; `new = [p for p in places if not session.is_listed_place(p)]`; each → `session.add_manual_entity(p)`; `new` not empty → the existing "Added … entity" line; else Q2's line through `display_info_message` (approved text, byte for byte).
4. **The widening, in core (the PO's F1):** `DocumentProcessor._widen_added_places(entities)` (static), called in `_run_validation` on `known_entities + validated_unknown` (`:379`), so the names stored in the mapping database and accepted without review count too: for each entity whose `source` is `ADDED_BY_HAND_SOURCE`, the spans of every other entity of the list with the same `context_label`; while the place partly overlaps one of them (they overlap, and neither holds the other), widen it to their union; a widened place is `dataclasses.replace(place, start_pos=…, end_pos=…)`, its text and type kept (AC14 (d), Lionel's Q4); every other entity, and the order, unchanged. `get_validated_entities` does not change. The desktop app does not call `_run_validation`, so it is not affected (10.17 decides its own).
5. One row per name: unchanged (`_resolve_pseudonyms`' cache by mapping key and type).

**AC1 and AC14 (d), a correction that partly overlaps another written name (v1.4; `core/document_processor.py`, and `validation/` if the dev marks corrections there).**
1. The widening of AC3's item 4 above runs on every **typed** place of the list sent: a place added with [A] (`ADDED_BY_HAND_SOURCE`) and a place corrected with [E] (including [E] then [T], and [C] after [E]). The rule is AC precisions, "AC1 and AC14 (d), a correction…": the same loop, the same "partly" test, the text and type kept, every other entity and the order unchanged. **Every place [E] reaches counts as typed** (v1.5): [E] corrects every occurrence of its group, so each corrected occurrence, at each place and in each cell, is widened on its own, not only the corrected name's first place. The PO's mutant (`rgpd-analysis/r1015/po/n4/mut_own/`: the prototype, but a correction counts as typed only at the corrected name's first place) passes T16-T19 and the 36 others and fails only T20 and T21 (measured, Reproduction Evidence v1.5); whatever mechanism the dev chooses (item 2) must mark or recognise every corrected occurrence.

A [T]-only retype or a [C] on a detected name keeps the detected text and span, so it is not typed.
3. Ties need no code: two typed places that partly overlap each other both widen to the same span, and `_apply_replacements` (and the per-cell writer) keep the first of two equal spans, since `sorted(…, key=(start, -end))` is stable: the first in the list sent gives the pseudonym.
4. Not changed: `_locate_modified_span`, `_apply_replacements`, `_apply_tabular_replacements`, `_resolve_pseudonyms`, `_check_cells`; no new text, no new error (a runtime stop for a leftover partial overlap would be new user copy; the widening removes the case, and T16-T19 pin it).

**What the user sees:**
