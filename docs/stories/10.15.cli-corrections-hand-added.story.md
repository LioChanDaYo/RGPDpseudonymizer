## Acceptance Criteria

1. **AC1 — The cell is kept ([E], [T]):** in the CLI, on a spreadsheet, a name corrected with [E], retyped with [T], corrected then retyped, or given a custom pseudonym after a correction keeps its cell. It is replaced in that cell, at every place of its group, and its stored row matches what is written.
2. **AC2 — A correction is found inside its cell:** a correction is located in the text of the cell the name came from, not in the joined review text. Where it is not found there, that place keeps its span, as on the text path (`_locate_modified_span`).
3. **AC3 — A name added with [A] is replaced at every place (Lionel, 2026-10-16):** every place of that name and type, that is every whole-word occurrence of the exact text added: in a text document, everywhere in the text; in a spreadsheet, in every cell where it occurs, each place with its cell and its position in the cell. An occurrence inside a longer word is not a place. A place where the detector found the same name with the same type stays with that name's group and its decision, as a decision on a row added by hand acts on that row only in the desktop app (10.10). One row is stored for the name, as today. The SM states how a place that overlaps another name already written is handled; no part of the added name stays in clear there.
4. **AC4 — No silent drop, checked before anything is saved:** before any row is saved (`_resolve_pseudonyms`, `:710`), every replacement of a spreadsheet is checked against the cells. If one matches no cell, the run stops with an error: no output file, no new mapping row and no success message. The error text is user copy (AC6).

14. **AC14 — The places of a name added with [A], exactly (story-level; Lionel's "Fix before release (Rec.)", Q3 "A: Hyphen joins (Rec.)" and Q4 "A: Name you added (Rec.)", 2026-10-16; epic AC3).**
    - **(a) A place (Lionel's Q3)** is an occurrence of the exact text typed (the same characters, capitals and accents included) where neither the character just before it nor the character just after it (when there is one) is a letter, a digit, an underscore (Python's Unicode `\w`) or a hyphen (`-`, U+2010 or U+2011). So "Zorbalix", "Saint-Zorbal", "Zorbal-Quentrix" and "anti-Zorbal" hold no place of "Zorbal" (inside a longer word: a hyphen joins words), while "Zorbal.", "(Zorbal)" and « Zorbal » do; an apostrophe is not a word character, so an elided article in front ("l'", "d'") does not stop a place. In a spreadsheet each cell's text is searched on its own, so a place never spans two cells; each place carries its cell (`context_label`) and its position in the cell. Places are read left to right and do not overlap each other.
    - **(b) Places already in the review are not added.** A place where the detector found the same text with the same type (same span, same cell) keeps its own review and decision (10.10), whatever the user decides on its group before or after the add. A place added by an earlier [A] of the same text and type is not added twice.
    - **(c) Each new place** becomes one added review with one ADD decision (`add_manual_entity`), as one [A] does today, and is sent at finalization as today: an added place is always sent. It carries `source="manual"`, the marker the desktop app already gives a row added by hand (`gui/models/validation_state.py:1203`), so (d) can find it in the list sent. One mapping row is stored for the name (one row per text and type, `_resolve_pseudonyms`), as today. The final screen's "➕ Added" counts places, as "✓ Confirmed" does.
    - **(d) A place that partly overlaps another name that is written (Lionel's Q4)**, in the same text or cell, neither span holding the other, is widened to cover both, again until it overlaps no other name partly, and the whole span is written with the added name's pseudonym. "Another name that is written" is every name sent: found or corrected in the review, another place added by hand, **and a name already stored in the mapping database, accepted without review** (`_run_validation`, `core/document_processor.py:331-359`; the PO's F1). Nothing of either name stays in plain text there. The name already there keeps its row and its own pseudonym everywhere else; at this place its pseudonym does not appear. A place that lies inside a longer place that is written is covered by it, and a place that holds a shorter one is written whole, both as today (the writer keeps the first, longest span, `core/document_processor.py:836-843`).
    - **(e) What the user reads:** no place at all: "'%1' not found in document" (unchanged); one or more new places: "Added %2 entity: %1" (unchanged); places but none new: Lionel's approved Q2 line, with the usual ℹ️ in front (`display_info_message`): « '%1' is already in the review as %2 at every place: nothing added » (%1 = the text typed, %2 = the type typed; Lionel approved it on "'Zorbal Quentrix' … PERSON …").

### Product Constraints (non-negotiable, verbatim from the epic)

[Source: prd/epic-10-v2.3-detection-precision-quick-wins.md#Product Constraints]

These apply to every story in this epic. A story that cannot meet its goal inside them stops and goes back to Lionel; it does not relax them.

1. **Local NLP only.** No LLM, no generative model, no API call, no cloud service, no telemetry. Every change is a deterministic rule, lexicon or pattern that runs offline.
2. **No encoder NER models.** Introducing a transformer/encoder NER model (e.g. CamemBERT-NER) is a Lionel decision that belongs to Epic 9. It must not be introduced in this epic, including as an optional dependency or experiment committed to the repo.
3. **Mandatory human validation stays.** No auto-accept mode, no `--no-validate`, no confidence-based skipping. Precision gains reduce the reviewer's workload; they do not replace the reviewer.
4. **No user data** for training, tuning or evaluation. All corpus and held-out documents are synthetic.
5. **Recall over precision.** Missing a real person is worse than showing an extra candidate. Any drop in overall recall or in any per-type recall needs Lionel's sign-off (gate G3).
6. **No public accuracy claim without CI evidence.** Every number that reaches README, FAQ, docs, CHANGELOG or the QA report comes from a cited CI accuracy run (gate G1).

For 10.15: constraints 1, 2 and 4 hold trivially (no detection change, no model, no data; the place search is a local string match). Constraint 3: validation stays mandatory; [A] still needs the user's typed name and type, and a found place keeps the user's own decision. Constraint 5: no detection change; the fix removes three paths that left accepted names in plain text, and the new check stops a run rather than write one. Constraint 6: the CHANGELOG entries carry no accuracy number.

**AC2, a correction is found inside its cell (`validation/models.py`, `validation/workflow.py`, `core/document_processor.py`).**
1. `ValidationSession.cell_texts: dict[str, str] = field(default_factory=dict)` (cell reference → cell text; empty for a text document) and `text_of(entity) -> str`: the cell's text when `entity.context_label` is one of `cell_texts`, else `document_text`.
2. `ValidationWorkflow.run(…, cells: dict[str, str] | None = None)` fills `cell_texts` (the session `:96-99` and the manual flow's session `:621-624`) and passes `cells=cells` **by keyword** through both restarts (`:126-133`, `:144-151`) and to `_manual_entity_addition_flow(…, cells=cells)`; `run_validation_workflow(…, cells=None)` passes `cells=cells` to `run`. **AC3, [A] at every place (`validation/models.py`, `validation/workflow.py`).**

`### Fixed`, two new bullets (AC7; the PM may prefer other wording; they quote neither Q1's nor Q2's text):

- **Command line: a name you correct or retype in an Excel or CSV file is now replaced (Story 10.15).** A name corrected with [E] or retyped with [T] (or both, or corrected and then given your own pseudonym with [C]) was left in clear in its cell, while its pseudonym was stored in the mapping database. This was in every earlier version. Now it is replaced in its cell, at every place of its group, with the pseudonym stored for it. A run where a name you validated cannot be placed in its cell now stops with an error, before the output file is written and before any pseudonym is stored.
- **Command line: a name you add with [A] is now replaced at every place (Story 10.15).** It was replaced only at the first place found, and in Excel and CSV files at no place, while its pseudonym was stored; the first place could even be inside a longer word. This was in every earlier version. Now every place of that name and type is replaced: every occurrence of the text you typed as a whole word, in the text or in every cell. A name inside a longer word is not replaced, and a hyphen joins words: a name inside a hyphenated word, such as « Saint-… », is not replaced; add the whole hyphenated word if it is a name. A place where the detector found the same name with the same type keeps the decision you made there. Where the name you add partly overlaps another name, the whole span takes the pseudonym of the name you added, so nothing of either stays in clear. Detection, the database schema and the accuracy figures do not change.
