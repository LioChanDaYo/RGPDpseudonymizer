## Story

**Added by Lionel, 2026-10-16 (Codex release review):** "Leaks + new 10.11 bugs (Rec.)" (the question is quoted in Story 10.14). ### AC precisions (story-level)

- **AC1, the rule, exactly.** A **name** is a mapping key (`mapping_key`: titles, and for a place a leading preposition, removed; spaces collapsed). A pseudonym's **runs** are those Q-C reads with Q-I's rule (`_document_runs`): for a person every run of consecutive whole words, without a linking word that another word of the pseudonym follows on its own; for an organisation or a place, the whole pseudonym. A run **repeats** a name when its words occur in the name as consecutive whole words with the run's own separators (a space for any whitespace, a hyphen, an apostrophe), compared folded (accents and capitals ignored), with **no** capital required: the comparison `_capitalised_occurrence` makes with the document, minus the capital (PO F1's separator rule kept: next to « zorbal-quentrix », the run "Quentrix" of "Xantor Quentrix" repeats it, while the run "Zorbal Quentrix", with a space, does not; the pseudonym "Zorbal Quentrix" is still refused, by its one-word runs). The refusal is `REAL_NAME`, with `%2` = the run found. The order inside `REAL_NAME` is per run, longest first: the document's capitalised words, then the review's names; then Q-C2's stored full names, as today.
- **AC1, "the name it replaces"** is always among the names: the name's mapping key, as the check receives it. So "quentrel zorbalia" or "Xantor Zorbalia" for « quentrel zorbalia » is refused even when it is the only name of the review (T1[whole_name, surname], T9[whole_name, surname], T3[own_surname]).
- **AC1, "every name of the review that is not rejected", when the pseudonym is set:**
  - **Desktop** (`custom_pseudonym_refusal`): the mapping keys of the entities every row not rejected would send (pending, accepted, corrected, retyped, added by hand), expanded to their variant occurrences exactly as `expand_validated_entities` expands the rows it sends (single-document review: a row stands for its variant occurrences, each with its own text; T10). A rejected row does not count, whether rejected on its own or with its group (T11[rejected_name]).
  - **Command line** (the [C] checker): the mapping keys of the entity each review not rejected sends (pending, confirmed, modified, added: `ValidationSession._sent_entity`), **plus the names known in the mapping database**, which `_run_validation` sends to the file without review (`core/document_processor.py:331-359`, `:379`). Without them a pseudonym accepted when set would be refused at finalization (T1[known_name]; mutant m1). A known name is stored, but Q-C2 counts only a whole stored name, so "Xantor Zorbix" next to a known « quentrix zorbix » passes Q-C2 and must be refused here.
- **AC1, "at finalization, the names sent to the file":** the mapping keys of the entities `_resolve_pseudonyms` receives (`validated_entities`; in the command line the known names are among them). Computed only when the run holds a custom pseudonym (AC10).
- **AC1, why set time counts more than finalization:** every name sent at finalization was a name not rejected when the pseudonym was set, unless the user changed the review afterwards: added a name by hand, corrected a row into a new name, or accepted a row they had rejected. Only then can a pseudonym accepted when set be refused at finalization, with the finalization error (no file, no row; the desktop review stays open). The PM's cost, recorded: a lowercase false detection still to review blocks a pseudonym until it is rejected (T12: "grâce" detected and pending blocks "Grace Vellion"; rejected, it no longer does).
- **AC1, "An organisation's or a place's pseudonym is compared whole, the same way":** the whole pseudonym against the runs of every name of the review (T13: « zorbaville », ORG, refuses "Zorbaville"). A person's name word inside a longer organisation or place pseudonym is not compared, as for the document's capitalised words (10.11 A3; QA's OBS-001 backlog; SM follow-up (c)).
- **AC1, unchanged:** the document's other lowercase words still do not count (T2, T4, T11[qc_grace_vellion, qc_xantor_avril]: Lionel's Q-C preview); Q-C2 still counts whole stored names only; Q-I's linking words are not compared alone with a review name either ("Le" in a review name never blocks "Xantor Le Velmar"; "Xantor Le" at the end is compared).
- **AC2, the rule, exactly.** The guard reserves, for each stored or registered custom row of a person, every beginning and every ending of its pseudonym (one or more whole words, the whole one included), folded, **each with its owners**: a real word of that row, in a role ("first" or "last"), that already has that value as its part in that role in the rows (its own stored part, or the same real word's part in another row; QA GUARD-001). A one-word name (`person_parts` gives a first name only) owns its part in either role, because the engine matches a lone word as a first or a last name (`_handle_standalone_component`, `pseudonym/assignment_engine.py:383-448`; 10.11's T36[last_name_later_run] needs it; mutant m4). A generated row **takes a reserved value** when:
  - its first part, folded, is reserved and the row's real first name, in the role "first", is not one of its owners;
  - its last part, folded, is reserved and the row's real last name in the role "last" is not one of its owners (for a lone name whose last part the engine matched, `last_name` is empty and the lone word is the real last name; a lone name's freshly drawn last part has no owner);
  - its full pseudonym, when it differs from its parts (a pseudonym of several parts, or an organisation's or a place's), is reserved at all.
  Such a row is drawn again by `_assign_untaken_pseudonym`, unchanged except its argument's type: the redraw keeps no component link, so any reserved value is refused there. QA's cases: "Xantor" drawn as a last name next to the custom "Xantor Vellion" (T5[first_part_as_last], T8), "Vellion" as a first name (T5[last_part_as_first]), "Xántor" and "Véllion" in their own roles (T5[first_part_accented, last_part_accented]), and the custom's own real last name "Zorbalia" used later as another person's first name, drawn "Vellion" (T5[own_word_other_role]; mutant m3). ### Fix Design (pre-decided; the product rules are Lionel's and the PM's reading the PO found faithful; no new text)

Rules, function names and signatures; the dev writes the code. The SM's prototype implements them (Reproduction Evidence, items 3 to 6); it is not given to Forge.

**AC1 (#8): the review's names count whatever their capitals.**
1. **The comparison.** In `core/custom_pseudonym.py`, the body of `_capitalised_occurrence(candidate, words)` becomes a shared `_occurrence(candidate, words, capitalised: bool)`; `_capitalised_occurrence` calls it with `capitalised=True` (its result unchanged). With `capitalised=False` the capital test is skipped; the folded words and the separator kinds are compared as today.
2. **The check.** `check_custom_pseudonym(stored_rows, name, entity_type, pseudonym, document_text, other_customs, words=None, review_names: Iterable[str] = ())`. Before the real-name loop, the names are `name` and every entry of `review_names` (non-empty, without repeats), each read with `document_words`. In the loop over `_document_runs(pseudonym, entity_type)` (unchanged), a run is refused (`REAL_NAME`, `%2` = the run) when `_capitalised_occurrence(run, words)` is true, as today, **or** `_occurrence(run, name_words, capitalised=False)` is true for one of the names. The Q-C2 loop after it is unchanged. The docstring names Story 10.16 and the PM's reading of Lionel's #8 decision.
3. **Desktop** (`gui/models/validation_state.py`). A private helper does `expand_validated_entities`' expansion on a given list of (row, entity sent) pairs; `expand_validated_entities()` calls it with `_validated_rows()` (its behaviour unchanged). `_review_names()` calls it with every row not REJECTED, each with the entity it would send (`_edited_entity(review)` when edited, else `review.entity`), and returns the mapping keys of the result (`mapping_key(text, type)`), without repeats. `custom_pseudonym_refusal` passes `review_names=self._review_names()`.
4. **Command line.** `PseudonymChecker` gains a fifth positional parameter, the review's names (`Iterable[str]`). `ValidationWorkflow` gets a static helper beside `_sent_name` that returns the mapping keys of the entity every review not REJECTED sends (`ValidationSession._sent_entity(review)`: pending, confirmed, modified and added reviews), and the [C] branch passes it as that argument. `_build_custom_pseudonym_checker(ctx, document_text, known_entities: list[DetectedEntity] | None = None)` keeps the known names' mapping keys and calls `check_custom_pseudonym(…, review_names=[*review_names, *known_names])`; `_run_validation` passes `known_entities` to it, inside the same `run_validation_workflow(…)` call, as the checker's argument.
5. **Finalization.** `_register_custom_pseudonyms(…, sent_names: Iterable[str] = ())` passes `review_names=sent_names` to each check. `_resolve_pseudonyms` passes `sent_names` = the mapping keys (`_normalize_entity_text`) of `validated_entities`, computed only when `custom_pseudonyms` is not empty.

**AC2 (#6): the guard keeps roles and spellings.**
1. **The reservation.** `untracked_custom_values(rows)` (name kept) returns `dict[str, frozenset[tuple[str, str]]]`: each folded value (every beginning and every ending of a custom person row's pseudonym, as today, nothing left out) → its owners, `(folded real word, "first" | "last")`. The parts a real word has are read by role (`first_name` with `pseudonym_first` as "first", `last_name` with `pseudonym_last` as "last"; roles no longer merged). A custom row's real words are `person_parts(full_name)`: the first name in the role "first" and the last name in the role "last"; a one-word name in both roles. A real word, in a role, owns a value when it has that value as its part in that role in the rows. Type aliases are fine (`Owner`, `CustomReservations`).
2. **The check.** A function in `core/custom_pseudonym.py` (for example `takes_custom_value(entity, reserved) -> bool`) applies the rule of AC precisions, AC2 to a generated `Entity` (its first part with its real first name; its last part with its real last name, or, for a lone name with no first part, the lone word; its full pseudonym, when it differs from its parts, with no owner). `_uses_custom_part` returns it (still `False` when nothing is reserved).
