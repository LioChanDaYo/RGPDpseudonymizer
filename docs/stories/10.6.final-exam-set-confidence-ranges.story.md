## Acceptance Criteria

AC1 to AC10 are the epic's Story 10.6 ACs, copied word for word. The story-level precisions that follow add detail; they do not change the epic text.

**PR A: confidence ranges (scorer-side reporting only)**

1. **AC1 — Bootstrap ranges in the accuracy output.**
   - The accuracy suite prints a 95% bootstrap confidence range for P, R and F1. It does so for Overall and for each type, on the main corpus and on the held-out set.
   - Resampling is by **document**, with replacement, because entities in one document are not independent. Each resample re-sums TP/FP/FN and recomputes P/R/F1. The range is the percentile interval.
   - The number of resamples and the seed are fixed and printed, so the output is deterministic.
   - New labelled lines are added (e.g. `[CI95 Overall] …`, `[HELD-OUT CI95 ORG] …`), each stating `unit=document` and the document count.
   - The held-out ranges are aggregates. No per-document held-out number is printed or stored.
2. **AC2 — Metric definitions unchanged.** `match_entities`, `_match_key` and the P/R/F1 formulas do not change. The existing `[Overall]`/`[PERSON]`/`[LOCATION]`/`[ORG]`/`[HELD-OUT …]` lines keep their exact format. PR A's G1 run shows these eight lines byte-identical to the previous merged run on the same detector code.
3. **AC3 — Paired delta for story-to-story comparisons (main corpus only).**
   - The accuracy artifact also stores the main-corpus per-document, per-type TP/FP/FN as a JSON file. The main corpus is not blind.
   - A script computes the paired bootstrap range of the delta between two runs (same documents, resampled together).
   - From PR A's merge on, a detector story that reports a precision or F1 gain states whether that gain is outside the paired range.
   - Held-out has no paired delta, because that would need per-document held-out output.

**PR B: final-exam set**

4. **AC4 — Brief and author.**
   - The set has 30 synthetic French documents (Lionel, Q2). The formats are messier than the main corpus: email threads with quoted replies, PDF-style hard line breaks, tables flattened to text, mixed case, headers and signatures.
   - 15 documents are planted with the known hard-case categories and 15 are natural, with no planted case (Lionel, Q6). The half each document belongs to is recorded with the set, so AC8 can score each half.
   - The author is GPT via `codex exec` (Lionel, Q1). It is **not** a rule-writing agent.
   - The author brief lists formats and hard-case categories. It names categories only, never corpus examples. It contains no GUIDELINES text and no corpus or held-out text. Lionel approves the brief before any generation.
   - No real public figures and no real people. No user data, no copy of real records (product constraint 4).
   - An annotator who meets a real person or public figure flags it, and the name is replaced consistently before freeze.
5. **AC5 — Double blind annotation, with agreement reported.**
   - Two independent annotations are made under `tests/test_corpus/annotations/GUIDELINES.md` (Lionel, Q3):
     - Annotator A is GPT via `codex exec`.
     - Annotator B is Kimi (Moonshot), or Gemini if Kimi access fails.
     - Neither sees the other's output. Neither is pre-annotated by the detector or by any auto-annotator.
     - Lionel does no hand annotation. Claude agents do not annotate, because they write the rules.
   - Inter-annotator agreement is reported per type as pairwise span F1. It uses the scorer's own matching (exact text and type after `_match_key`, one-to-one). Disagreements are counted by class.
   - Lionel adjudicates the disagreements only, under GUIDELINES, after 10.4 merges (Q4). The adjudication is logged. A case GUIDELINES does not cover goes to Lionel as an amendment, as in 10.1.
   - **Spot-check:** Lionel also checks about 3 documents where the two annotations agree, to catch errors both models share. The finding (the number of shared errors, by class) is reported next to the agreement figures.
   - The report holds only agreement figures, spot-check counts and classes, never entity text.
6. **AC6 — Frozen, adjudicated, then committed.**
   - Authoring and annotation happen in an isolated workspace outside the repo. Orchestrating agents handle only paths, hashes and counts, and never print document or annotation content.
   - **Freeze, before 10.4 merges:** once both model annotations are done, the 30 documents and the two annotations are frozen in that workspace. Their sha256 fingerprints are recorded in this story (the freeze record), as proof that the texts are not edited later. Nothing is encrypted.
   - **Adjudication, after 10.4 merges:** Lionel adjudicates and spot-checks (AC5). Any adjudication view shown to him is produced by a deterministic local script. Agents run that script without printing or reading its output.
   - **Commit, after adjudication:** the documents, the adjudicated annotations and the adjudication log (both model annotations, Lionel's decisions, the spot-check) are committed as plain files under `tests/test_corpus/final_exam/`. At commit time, the documents' sha256 fingerprints are checked against the freeze record; a mismatch stops the commit and goes to Lionel. The sha256 of the adjudicated annotations is added to the record.
   - The folder is outside every path the regular accuracy job loads, and outside `accuracy.yaml`'s push `paths`.
   - Storage: plain files in the repo, committed only after 10.4 merges. No encryption, no key, no GitHub environment (Lionel, Q5 reversed, 2026-10-09).
7. **AC7 — Leakage guard covers the final exam.**
   - A plain-text check of the same kind as the held-out guard: `tests/unit/test_held_out_leakage.py`, or a sibling test, takes the final-exam-only strings from the committed final-exam annotations (normalized as `_match_key` does, and not occurring in the main-corpus text) and checks `gdpr_pseudonymizer/resources/**` and `tests/unit/**` for them. It reports paths and hashes only, never the string. There is no salted hash list.
   - It is active from the AC6 commit onward, on every CI run. Its first run checks every file that 10.3c and 10.4 added.
   - The held-out-blind rule (10.3b AC12) applies unchanged: any real string in a new test or resource must occur in main-corpus text or be approved by Lionel.
8. **AC8 — Scored exactly once, and enforced.**
   - **Trigger:** the final exam runs only on a manual `accuracy.yaml` dispatch whose `final_exam` input equals `final exam`. The job has no environment binding (Q5 reversed, 2026-10-09).
   - **Job:** before scoring, the job checks the folder's sha256 fingerprints against the freeze record (the adjudicated annotations against the value added at commit, AC6). It then runs the usual suite and appends `[FINAL-EXAM Overall]`/`[FINAL-EXAM PERSON]`/`[FINAL-EXAM LOCATION]`/`[FINAL-EXAM ORG]` lines plus their CI95 lines to `accuracy-output.txt` in the `accuracy-results` artifact. The regular job is skipped in that run, so there is one `accuracy-results`.
   - **No exam text in public CI logs:** errors print the error class and a document id only; the detector logs at CRITICAL in that job; pytest runs with `--tb=short` or an equivalent, so a failing test never prints its arguments (QA SEC-001, PR A).
   - **Per half (Q6):** the same Overall and per-type lines, each with its CI95 line, are also printed for each half: `[FINAL-EXAM PLANTED …]` for the 15 planted documents and `[FINAL-EXAM NATURAL …]` for the 15 natural ones.
   - **Why this shape:** the close-out evidence must be a G1 run as the Gates block defines it (an `accuracy.yaml` run, cited by ID, lines pasted from `accuracy-results`). With this shape G1 and G2 apply word for word. This is why the job lives inside `accuracy.yaml` rather than in a separate workflow.
   - **Ledger:** a committed ledger (e.g. `tests/test_corpus/final_exam/RUNS.md`) records the one scored run: run ID, commit, date, and Lionel's approval. A re-run is allowed only for an infrastructure failure at the **same** commit, with the reason recorded. A run at a later commit is a second look, and it is forbidden within Epic 10.
   - **Numbers are never inputs:** final-exam numbers are never used for a decision or for tuning. No agent opens, lists or greps the set, in its workspace outside the repo or in `tests/test_corpus/final_exam/`. From the start of 10.6 authoring, every later story's Dev Notes restate this, next to the held-out isolation rule.
   - **Before the real run:** QA proves the job on a **dummy** fixture (invented text, with its own fingerprint record) and never on the real set. This proves the job wiring (trigger, fingerprint check, skipped regular job, artifact lines, quiet logs) without spending the one real run.
9. **AC9 — Close-out reporting and the public number.**
   - At Epic 10 close-out (10.4 merged), the QA report and the epic Close-Out Record carry the main, held-out and final-exam figures, each with its range. The lines are pasted verbatim, because `accuracy-results` artifacts are kept 30 days (`accuracy.yaml:83`).
   - Lionel decides which figure is public: main, held-out, final exam, or a stated combination. This is recorded under G7 and the Epic 10 G7 interpretation. README/README.fr, FAQ, docs index and tutorials then change once, from that run.

### AC precisions (story-level)

- **AC1, labels *[story]*:** the epic's labels are examples ("e.g."). `[HELD-OUT CI95 …]` would be picked up by the held-out extraction patterns `^\[HELD-OUT` and `\[HELD-OUT`, so it is **not** used. Every new label starts with `[CI95 `: `[CI95 Overall]`, `[CI95 PERSON]`, `[CI95 LOCATION]`, `[CI95 ORG]`, `[CI95 HELD-OUT Overall]`, `[CI95 HELD-OUT PERSON]`, `[CI95 HELD-OUT LOCATION]`, `[CI95 HELD-OUT ORG]`. PR B adds `[CI95 FINAL-EXAM …]` lines on the same scheme. The exact line format, the resampling procedure, the resample count, the seed and the undefined-metric rule are in Dev Notes "PR A Design"; the consumer check is in Dev Notes "Line Labels and Consumers".
- **AC1, undefined metrics *[story]*:** when a resample has no denominator for a metric (P: TP+FP = 0 for that label; R: TP+FN = 0; F1: P or R undefined), that resample is left out of that metric's distribution and counted. Every CI95 line prints the three counts (`undef_P=`, `undef_R=`, `undef_F1=`). A metric with no defined resample prints `[n/a]`.
- **AC2 *[story]*:** "byte-identical" is checked with `diff` on the eight lines, extracted with the canonical patterns E1 and E2 (Dev Notes "Line Labels and Consumers") from PR A's G1 artifact and from `37678069251`. `tests/accuracy/conftest.py` is not modified in PR A, and no existing class, helper or `print` in `tests/accuracy/test_ner_accuracy_validation.py` is edited.
- **AC3 *[story]*:** the JSON is `accuracy-per-document.json` in the `accuracy-results` artifact, and the script is `scripts/accuracy_paired_delta.py`. "Outside the paired range" means that the paired 95% range of the delta (candidate − baseline) does not contain zero (`excludes_0=yes`); for a gain, its lower bound is above zero. No run of the 10.3b detector code carries the JSON yet: PR A's G1 run, and the `main` push run after PR A merges, are the first, and the latter is 10.3c's paired baseline. Held-out per-document counts exist only in memory, inside the held-out test, to compute the four held-out CI95 lines. They are never printed, stored, written to the artifact or put in an assertion message.
- **AC4–AC6 *[story]*:** the isolated workspace, the freeze record and the adjudication mechanics are in Dev Notes "PR B Design". Since the Q5 reversal (2026-10-09), nothing is encrypted and no key exists. The freeze is a sha256 fingerprint record that an agent writes without printing content (B7.3). After adjudication, plain files are committed and checked against it (B11.1).
- **AC5, spot-check *[story]*:** "about 3 documents where the two annotations agree" means the agreed spans, and anything both annotators missed, in 3 documents drawn with a fixed seed (Dev Notes "PR B Design").
- **AC7 *[story]*:** the guard is plain text, like the held-out guard. It reuses that guard's helpers and its per-file allowlist mechanism, (path, sha256 of the key) with each entry approved by Lionel, in a sibling allowlist file (Dev Notes "Final-Exam Leakage Guard"). There is no salted hash list. Hits in the name and geography dictionaries are expected; they are found before the commit (B11.2) and Lionel decides each one.
- **AC8, labels *[story]*:** 12 point lines, `[FINAL-EXAM Overall|PERSON|LOCATION|ORG]`, `[FINAL-EXAM PLANTED …]` and `[FINAL-EXAM NATURAL …]`, in the formats of the `[HELD-OUT …]` lines, each followed by its `[CI95 FINAL-EXAM …]` line (`[CI95 FINAL-EXAM PLANTED ORG]`, …). The regular extraction patterns (E1–E4) match none of them; `^\[FINAL-EXAM` matches the 12 point lines only.
- **AC8, quiet logs *[story]*:** the `final_exam` job runs pytest with `--tb=short`, and `TestFinalExamMetrics` takes no exam data as a test argument (QA SEC-001, PR A). A forced failure on the dummy fixture proves it (B8.5).
- **AC9 *[story]*:** the epic's `accuracy.yaml:83` is the line `retention-days: 30` in `accuracy.yaml`. PR A adds lines above it, so this story cites it by content, not by line number. The value stays 30.

### PR A Design (AC1–AC3)

**Constants** (`tests/accuracy/bootstrap.py`):
- `RESAMPLES = 10_000`. Percentile intervals are usually given with at least 1,000 resamples; 10,000 keeps the bounds' dependence on the seed small, and costs about 10,000 × 25 index draws for the main corpus, well under a second. With a fixed seed the output is deterministic in any case: the count only limits how far the printed bounds would move under another seed (measured once, A8.5).
- `SEED = 20261008` (the date of this draft). It is fixed before any range was computed, so it cannot have been chosen to make the ranges look good. It does not change within Epic 10, so ranges stay comparable from story to story.
- `LABELS = ("Overall", "PERSON", "LOCATION", "ORG")`; confidence 95%, bounds at 2.5% and 97.5%.

**Per-document counts** (`doc_counts(result)`): for one `DocumentResult`-like object, a mapping label → (TP, FP, FN), computed exactly as `_aggregate` (`test_ner_accuracy_validation.py:30-44`): `Overall` = (`len(true_positives)`, `len(false_positives)`, `len(false_negatives)`); for a type, TP counted on the ground-truth type of each pair, FP on the detection type, FN on the ground-truth type. The function takes any object with those three lists (a `typing.Protocol`), so the module never imports the test module.

**Resampling** (identical in the suite, in the script and in QA's recompute):
1. `rng = random.Random(SEED)`, a fresh generator for each set of lines (main, held-out, each final-exam subset, each paired comparison).
2. For each of the `RESAMPLES` resamples: `idx = [rng.randrange(n) for _ in range(n)]`, where n is the number of documents and documents are in loader order (the JSON's order). A document drawn twice counts twice.
3. For each label, sum TP, FP and FN over `idx`; decide which metrics are undefined (below); compute the defined ones with `compute_metrics`.
4. The same `idx` serves the four labels. For the paired delta, it serves both runs.

**Undefined metrics:** P is undefined when TP + FP = 0 for that label in that resample; R when TP + FN = 0; F1 when P or R is undefined. When both are defined and TP = 0, F1 is 0.0, as `compute_metrics` returns, and it is kept. An undefined resample is left out of that metric's distribution and counted in `undef_P`, `undef_R` or `undef_F1`.

**Percentile rule** (integers only, no interpolation): sort the m defined values ascending; lower bound = `v[(25 * m) // 1000]`, upper bound = `v[(975 * m + 999) // 1000 - 1]`. For m = 10,000 these are `v[250]` and `v[9749]`: 250 values lie below the lower bound and 250 above the upper bound. For m = 0 the range is `[n/a]`.

**CI95 line format** (one line per label; values to 4 decimals like the existing lines):

```
[CI95 <label>] P=[<lo>,<hi>] R=[<lo>,<hi>] F1=[<lo>,<hi>] unit=document docs=<n> resamples=10000 seed=20261008 undef_P=<k> undef_R=<k> undef_F1=<k>
```

- `<label>` is `Overall`, `PERSON`, `LOCATION`, `ORG`, or `HELD-OUT <type>` (PR B: `FINAL-EXAM <type>`, `FINAL-EXAM PLANTED <type>`, `FINAL-EXAM NATURAL <type>`).
- `<lo>`/`<hi>` are `f"{x:.4f}"`; a metric with m = 0 prints `[n/a]`.
- The ranges are not centred on the point value and are not printed with it; the point value stays in the existing line.
- The first line of a test's output starts with `"\n"` (A2.2).

**JSON** (`accuracy-per-document.json`, main corpus only; UTF-8, `ensure_ascii=False`, `indent=1`, final newline):

```json
{
 "schema_version": 1,
 "corpus": "main",
 "run_id": "<GITHUB_RUN_ID or null>",
 "commit": "<GITHUB_SHA or null>",
 "bootstrap": {"unit": "document", "method": "percentile", "confidence": 95, "resamples": 10000, "seed": 20261008},
 "labels": ["Overall", "PERSON", "LOCATION", "ORG"],
 "documents": [
  {"doc": "<main-corpus file name>", "Overall": {"tp": 0, "fp": 0, "fn": 0}, "PERSON": {"tp": 0, "fp": 0, "fn": 0}, "LOCATION": {"tp": 0, "fp": 0, "fn": 0}, "ORG": {"tp": 0, "fp": 0, "fn": 0}}
 ]
}
```

Documents are in loader order (`corpus_results` order). The main corpus is not blind, and its per-document overall counts are already printed by `TestPerDocumentBreakdown`. There is no held-out or final-exam counterpart, and no key or option to write one.

**Paired delta** (`delta`): the point delta for each metric is candidate − baseline, each computed with `compute_metrics` on that run's full sums. The range is the percentile interval of the per-resample deltas, using the same `idx` for both runs. A resample where either side is undefined is left out and counted. One line per label:

```
[PAIRED-DELTA <label>] dP=<+d> [<+lo>,<+hi>] dR=<+d> [<+lo>,<+hi>] dF1=<+d> [<+lo>,<+hi>] unit=document docs=<n> resamples=10000 seed=20261008 undef_P=<k> undef_R=<k> undef_F1=<k> excludes_0=P:<yes|no>,R:<yes|no>,F1:<yes|no>
```

Values use `f"{x:+.4f}"`. `excludes_0` is `yes` when the lower bound is above 0 or the upper bound is below 0. The script first prints `baseline run_id=<…> commit=<…>` and `candidate run_id=<…> commit=<…>`.

**Hand-off to 10.3c and 10.4 (AC3):** from PR A's merge on, a detector story that reports a precision or F1 gain runs `delta` between its baseline run's JSON and its close-out run's JSON, pastes the four `[PAIRED-DELTA …]` lines with both run IDs, and states whether the gain is outside the paired range. 10.3c's baseline JSON is the A10.6 run (or a fresh `main` dispatch on the same code). The 10.3c branch must contain PR A (cut from `main` after PR A merges, or rebased onto it), so that its own runs carry the JSON. The SM writes this into the 10.3c and 10.4 stories.

**Annotation template** (B5): the full text of `GUIDELINES.md`, then the output rules:
- return the whole document, character for character, with each entity wrapped as `⟦TYPE|text⟧`, where TYPE is `PERSON`, `LOCATION` or `ORG`;
- nest only where GUIDELINES allows it (a nested LOCATION inside an ORG, G7);
- do not change, add or remove any other character;
- after the document, either the single line `REAL-PERSONS: none`, or the line `REAL-PERSONS:` followed by each real person or public figure recognized, one per line. `convert` reads any case or trailing-punctuation variant of `none` (`None`, `NONE.`, `none!`) as none. Any other text after `REAL-PERSONS:` is a real-person flag (B6.2). A missing `REAL-PERSONS:` line is a format failure (B6.1). This replaces the strict parsing of v1.2.
The delimiters `⟦` and `⟧` (U+27E6, U+27E7) are checked to be absent from every generated document (B4.2), so tags never collide with text such as e-mail addresses in `<…>`.

**Convert** (`convert`): parses the tags with a stack (nesting allowed), strips them, and aligns the result to the document with a copy check that tolerates layout noise only:
- a whitespace run (spaces, tabs, line breaks, U+00A0, U+202F) on one side matches a whitespace run of any length on the other; this covers trailing spaces before a line break. At the very end of the text, a run may be missing on one side;
- the apostrophes `'`, `’`, `‘` and `ʼ` match each other, and so do the double quotes `"`, `“`, `”` and `„`;
- any other difference (a letter, a digit, other punctuation, a word added or dropped) is a failure (B6.1).
On success it maps every span boundary back to the document's own offsets (a boundary inside a whitespace run snaps to the nearest non-space character of the span), writes the main annotation format on the document's text, and reports only the count of tolerated characters. It never prints text.

**Agreement** (`agreement`):
- Annotator A is the reference and B the candidate, matched with `match_entities` from `tests.accuracy.conftest`: exact text and type after `_match_key`, one-to-one, nearest position. B's entities are wrapped as `DetectedEntity`.
- Pairwise span F1 per type and overall uses `compute_metrics` on those counts. It is symmetric in A and B.
- **Disagreement classes**, from the unmatched spans of both sides. A pair counts as one disagreement, a lone span as one, and each span joins at most one pair. Pairing is deterministic:
  1. Sort the unmatched spans of each side by (document, start, end, type).
  2. **type**: pair spans with the same offsets and different types.
  3. **boundary**: among the spans left, pair same-type spans that overlap and have different match keys. Each A span, in sorted order, takes the free B span with the largest character overlap; ties go to the B span that comes first in sorted order.
  4. **other**: among the spans left, pair spans that overlap in any other way, by the same rule as step 3.
  5. **one-sided**: every span still unpaired.
- Output: counts only.

**Adjudication view** (`view`, deterministic: the same inputs give the same bytes):
- `adjudication_view.html`: one block per disagreement, with id `fe_NN-dKKK` in offset order, its class, the surrounding lines, and A's and B's spans highlighted with their types.
- `decisions.tsv`: `id`, `class`, `decision` (empty), `note`. Decision codes: `A`, `B`, `BOTH`, `NONE`, `FIX:<TYPE>:<exact span text>` (the merge places a `FIX` span at the occurrence of the text nearest the disagreement, inside the shown context, and fails if there is none). `BOTH` is refused on a `type`-class disagreement: it would put two types on the same span.

The merge prints how many occurrences it added, and fails if there are none. These classes are the reported "shared errors by class", and the corrections go into the adjudicated annotations.

### Code review

- **`tests/accuracy/bootstrap.py`** matches the design.
  - Resampling is by document, with replacement (`randrange(n)`, n times). One draw per resample serves the four labels, and in the paired delta it serves both runs; the stub-draw tests prove both.
  - The percentile rule uses integers only and is symmetric for any m.
  - "Undefined" is decided from the denominators, so the 0.0 that `compute_metrics` returns for a zero denominator never enters a distribution. F1 = 0.0 with P and R both defined is kept. Every defined value comes from `compute_metrics`.
  - The module has no logging and loads no model. Importing it imports `tests.accuracy.conftest`, as the story asks, which runs that file's `configure_logging("WARNING")`; CI loads that conftest anyway.
- **Determinism.** The resampled golden test passes on Python 3.10, 3.11 and 3.12, on three OSes. QA reproduced the CI values with Python 3.12.3 (Linux) and 3.11.9 (Windows).
- **Held-out.** The per-document held-out counts are a local variable of `test_held_out_ranges`, and its only assert compares a plain integer. The failure path is SEC-001.
- **`scripts/accuracy_paired_delta.py`.**
  - Importing it leaves `sys.stdout` unchanged; the UTF-8 setup runs only under `__main__`.
  - Exit codes are as documented, except REL-001.

  - a document with no gold for a type;

  - duplicate names;

  - negative, float or bool counts;

### Findings

- **SEC-001 (low, not blocking): a held-out leak path that opens only if a test fails.**
  - **What happens.** When a test fails, pytest's default traceback (`--tb=auto`) prints the function's arguments. QA confirmed this with invented data on pytest 9.1.1.
  - **What would show.** If `test_held_out_ranges` (`test_ner_accuracy_validation.py:474`) ever failed, three places would show the start and end (about 240 characters) of `repr(held_out_results)`, that is, held-out document names and entity text: the public CI log, `accuracy-output.txt` and the JUnit failure text. If the error were raised inside the bootstrap, the raising frame's arguments would show too: for `_summed` (`bootstrap.py:211`), one label's held-out per-document counts.
  - **Why it is low.** Asserting on plain integers closes the assertion path, not this one, but nothing is printed while the tests pass. `TestHeldOutMetrics` (`:423`) already has the same exposure, so PR A adds almost nothing.
  - **Fix.** Fix both held-out test classes together, in one later benchmark PR, with the existing `len()` assert follow-up. Either take the fixture through `request.getfixturevalue(…)` and re-raise errors as a bare `RuntimeError(<class name>) from None`, or run the accuracy pytest with `--tb=short` or `--tb=native`. A QA probe shows that neither option prints arguments.
  - **PR B must design this out** of `TestFinalExamMetrics` and the `final_exam` job (B3.4, B3.5). The planned `RuntimeError` re-raise does not stop pytest from printing the test's fixture arguments. B8 can prove the fix with a forced failure on the dummy fixture.
- **REL-001 (low, nit).** `recompute --lines` on a file that is not valid UTF-8 raises an uncaught `UnicodeDecodeError`. The script then exits with 1 and a traceback instead of 2, because only `OSError` is caught (`scripts/accuracy_paired_delta.py:106-109`). Real artifacts are UTF-8. Catch it when the script is next touched.
