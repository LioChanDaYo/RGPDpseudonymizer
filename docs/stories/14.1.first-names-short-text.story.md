### Context: why a lone first name is missed today

- **The label map drops MISC.** `SpaCyDetector._map_entity_type` (`nlp/spacy_detector.py:194-213`) maps PER, LOC, GPE and ORG (and their long forms); every other label, MISC included, gives `None`, and `detect_entities` keeps only mapped entities (`:169-188`). spaCy's French model often labels a lone first name MISC: 1,507 of QA's 7,390 cases, and 79.9% of the misses (QA, `measure.log` (d)). The Doc is kept (`self._last_doc = doc`, `:166`; `last_doc`, `:237-244`), so a rule can still read the MISC spans.
- **How « Bonjour X, » already reaches PERSON.** Story 10.4's R-SAL-BARE (`hybrid_detector.py:1526-1563`) adds a regex PERSON for a known first name on a salutation line (`_salutation_lines`, `:1310-1359`): shape 1, one or two names alone on a line ending with a comma; shape 2, an opener of `salutations.yaml` (« Bonjour », « Merci », « Bonne initiative », « Félicitations ») then the name and `, . !` or the end of the line. "Known" means `NameDictionary.is_first_name` (`name_dictionary.py:81-91`) over `french_names.json`'s 451 names. So « Bonjour X, » works for those 278 library names that are also in `french_names.json` (0 missed of 278) and not for the 461 others (204 missed); « Merci X pour … » is not a salutation line (a word follows the name), nor is « Cordialement,⏎X » (no comma after the name).
- **The other 20%: spaCy finds nothing** (350 of 1,738 misses; 206 of them in « Réponse de X : »). No MISC rule reaches them; only a context rule (D) does.
- **What the user sees** (epic): a missed name is not in the desktop review list (`gui/workers/detection_worker.py:167-191`) and can be caught only by selecting it and using « Ajouter comme entité » (`gui/widgets/entity_editor.py:359-367`); if nothing at all was found, the panel says « Aucune entité détectée. Le document ne contient peut-être pas de données personnelles… » and « Continuer ▶ » is still offered (`gui/screens/processing.py:170-174`, `:317-319`).

### The candidates, measured (for Lionel's Q1)

**What each candidate does, in plain words.** spaCy, the language model the app uses, sometimes puts a lone first name in its "other" bucket (MISC), which the app throws away today; sometimes it sees nothing at all.
- **A:** when spaCy's "other" bucket holds exactly a first name of the app's pseudonym library, that word becomes a person. (QA's "span" reading.)
- **B:** when spaCy's "other" bucket holds a few words, each capitalised word in it that is a library first name becomes a person. (QA's "token" reading; the fix the epic simulated.)
- **C:** B, with two lists of first names (the library's 739 and `french_names.json`'s 451, 898 together, accents ignored, so « Elodie » matches « Élodie »), and two guards: a word right after a title (« M. », « Mme », « Dr. ») stays as today, so « M. Bernard » keeps its title; and a word right next to another capitalised word that is not a first name (« Microsoft Azure », « Azure SQL », « Bleu Céleste ») stays as today.
- **D:** a context rule that needs nothing from spaCy: a known first name right after « Bonjour », « Merci », « Réponse de », « De la part de », « Envoyé par » or « De : », alone on the line after « Cordialement », « Bien cordialement », « Bien à vous » or « Merci », or after a dash at the start of a line, becomes a person. Every cue word occurs in the main corpus, so no new word needs Lionel's approval. It is the only rule that reaches the misses where spaCy sees nothing (20% of today's misses; 206 of them are « Réponse de X : »).
- **CD:** C and D together. **Cfn+D:** C with `french_names.json` alone for spaCy's "other" bucket (so no « Azure », no « Ruby », which are only in the library's list), and D with both lists.

- **Detection now reads the default library's first names** (if the list includes them): a later edit of `neutral.json`'s first names changes detection, and does not trigger an accuracy run by itself (Project Structure Notes).
- **The command line's « No entities detected in document. »** (`validation/workflow.py:221`) is unchanged (epic: out of scope).

   The walk, exactly:
   ```python
   def _line_neighbour(doc: Any, i: int, step: int) -> Any | None:
       """The nearest non-space token before (step -1) or after (step 1)
       token i on the same line; None at a line break or the text's end."""
       j = i + step
       while 0 <= j < len(doc):
           token = doc[j]
           if "\n" in token.text:   # before is_space: spaCy makes a line break a space token
               return None
           if token.is_space:
               j += step
               continue
           return token
       return None
   ```
