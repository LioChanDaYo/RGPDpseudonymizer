### Context: the problem, re-measured (SM, 2026-11-24)

**How it was measured** (`sm161.py`). Every `tr()` and `translate()` call under `gdpr_pseudonymizer/gui/` read with Python's `ast` (its run-time string, and its raw source text for the escapes); both `.ts` files read as XML and as text (for their line numbers); the shipped `en.qm` and `fr.qm` loaded in a standalone `QTranslator` and asked `translate(context, source)`. The probe then builds the fixed `.ts` files and both `.qm` files in `…\r161\sm\out\`, exactly as Task 2 will, and measures them. It ran on the base and on Story 15.1's tip.

**What happens** (the epic's mechanism, confirmed). A `tr()` source written in Python with a `\u` escape is extracted into the `.ts` files without its backslash: « Ajouter comme entité » became the key `Ajouter comme entitu00e9`. The English is stored under that key, and the app asks with « Ajouter comme entité », so Qt finds nothing and shows the French source. Nine English translations were extracted the same way (« Continue u25b6 »).

### The guard

Three parts, each a test on CI. Together they hold "no gap" for the 39 calls (38 after Story 15.1) and keep it from happening again.

1. **G1, the code (`tests/unit/test_english_label_guard.py`).** Every `tr()` and `QCoreApplication.translate(context, …)` call under `gdpr_pseudonymizer/gui/` whose source is a string literal is read with `ast` (the call) and `ast.get_source_segment` (the literal's raw text, implicit concatenations included). The raw text is scanned with `\\(u[0-9a-fA-F]{4}|U[0-9a-fA-F]{8}|x[0-9a-fA-F]{2}|N\{[^}]*\}|.)`, which consumes an escaped backslash as one escape, so `\\u00e9` is not flagged. The test fails on any `u`, `U`, `x` or `N` escape and lists each as `file:line [context]`. `\n` (13 escapes in 7 calls) and every other escape are allowed.
   - **Why the escapes are rewritten rather than left and checked against `en.qm`:** a check "every `tr()` source written with a `\u` escape is in `en.qm`" covers nothing once the escapes are written as characters, and leaving them violates the project's rule (no `\u` escapes in `tr()`, Story 10.13 Coding Standards l.798; Story 11.4 l.192) and keeps the trap for the next `pyside6-lupdate` run. Rewritten, no `\u` is left for `lupdate` to break, and G1 keeps any new one out. The probe measured the rewrite: the same run-time string for 39 of 39 calls (38 of 38 after 15.1).
   - **The 39 (or 38) calls are then covered** by L1, L2 and K2: each of the 37 pairs they pass is asked of the shipped `en.qm` and must give the exact English. K1 proves each pair is still a source the code passes, in its file and class. Task 0's probe proves the 37 pairs are exactly the escaped calls' pairs on the rebased base, so no call is left out.
   - **The three working sources of `database.py`** (W1 to W3) are rewritten like the others; their `en.ts` keys already hold the real characters, so they keep working (K2 ×3, controls).
2. **G2, the `.ts` files (same file) ×2, `en.ts` and `fr.ts`.** Each file is parsed as XML; every `<source>` and `<translation>` text is scanned for `[uU][0-9a-fA-F]{4}`. A match fails the test unless its (context, field, matched text, full text) is in `REAL_WORDS`, an allowlist in the test.

The SM measured 0 matches outside the 29 broken keys and 9 broken translations, in both files, sources and translations, and 0 in every run-time `tr()` source (Context).
