## Story

**As a** user reviewing detected entities,
**I want** detected spans to stop at line breaks and at the end of the name,
**so that** a heading, a signature line or the rest of a sentence is not offered as one organisation or person, and no part of a name is left in clear text.

**Priority:** MEDIUM. First half of epic story 10.3 (split by Lionel, 2026-10-06; see Dev Notes "Split Rationale"). It carries the boundary work that story 10.2 handed over (Dev Notes "10.2 Handoff Placement"). 10.3b starts only after this story is merged.
**Change type:** Detector-only (G4). No annotation, scorer or held-out change in this story.
**Epic:** [Epic 10: v2.3 — Detection Precision Quick Wins](../prd/epic-10-v2.3-detection-precision-quick-wins.md) (story 10.3, split into 10.3a/10.3b)
**Branch:** `story/10.3a-boundaries-run-on-spans`, cut from `main` at `f75ad9a` (right after story 10.2 merged as PR #81).
**Baseline:** 10.2 merged close-out, G1 run H `37385301566` (head `9f68da8`), reproduced exactly on `main` by accuracy run `37424140809` at `f75ad9a` (push). See Dev Notes "Baseline".

### Product Constraints (non-negotiable, verbatim from the epic)

[Source: prd/epic-10-v2.3-detection-precision-quick-wins.md#Product Constraints]

These apply to every story in this epic. A story that cannot meet its goal inside them stops and goes back to Lionel; it does not relax them.

### Dry-Run Protocol (lessons from 10.2)

- **Reproduce first.** No dry-run number is trusted until the baseline dump reproduces run H exactly (1.1), and the re-merge of the pre-merge lists reproduces the dump (1.2).
- **Net, not gross.** `match_entities` (`tests/accuracy/conftest.py`) is exact text + type, one-to-one, with position only as a tiebreaker. A boundary fix can therefore show up as a TP gain, as a TP loss elsewhere, or as nothing. Re-score the **whole** post-rule dump and report the per-type net delta. STOP R and STOP G3 use the net delta.
- **Classify every lost TP:**
  - **position loss**: no detection now matches that annotation at its position, so it becomes an FN;
  - **taken over**: another detection now matches it;
  - **cross-position scorer artefact**: the lost TP was matching a same-text annotation elsewhere.
  Gained TPs are classified the same way (real fix vs artefact). 10.2 example: "AutoMotive SA" was kept clean at its position and still counted as a miss through re-pairing.
- **Coverage table** for every rule and composition: for each annotation that becomes a miss, is it still covered by a same-type span, covered by another type only, or uncovered? Also list every annotation that was fully covered by its own type in the baseline and no longer is (AC6 level 2), and every annotation of any type that loses its last cover of any type (level 2b).
- **Scripts:** use and extend `scripts/accuracy_dump_detections.py` (dump; `--record-dedup` records dedup drops), `scripts/accuracy_size_findings.py` (scoring, coverage, `VARIANTS`), `scripts/accuracy_org_loss_attribution.py` (attribution of new misses to rules), and `scripts/accuracy_segment_trim_dryrun.py` (V3-style in-script patching pattern). New scripts are named `scripts/accuracy_*.py`, use `Path(__file__).resolve().parent.parent`, and call `_load_corpus_documents()` only. Dumps and outputs are written outside the repo and are never committed. Run them via `cmd.exe` + `poetry run python`.
- **Pipeline order matters.** Dry-run each rule at the point where it will plug in (below), because filters before the dedup change which span wins a containment.

Generic reason: a name never crosses a line break (C2 rationale, Lionel 2026-10-04).
- **R-ORG (regex, 3.2): ORG name shape.** Name part = capitalised tokens joined by single `HSPACE` characters. Lower-case connectors (de, du, des, d', la, le, l', et, &) are allowed only between two capitalised tokens. **Glued elisions:** d' and l' (straight `'` or typographic `’`) attach to the following capitalised token with no space ("Cour d'Appel de Paris", "Chambre d'Agriculture d'Eure-et-Loir" stay whole; unit test with an invented "Cour d'Zorbal de Quentrix" shape). Pattern 1 may no longer start on a capitalised word followed by lower-case non-connector words before the name. Pattern 2 stops at the first lower-case non-connector word, comma or clause punctuation. Examples (invented):
  - "Quand la direction de Quentrix SA" → "Quentrix SA";
  - "Institut Zorbal à Zorbaville, notamment le Dr" → "Institut Zorbal";
  - "Agence Zorbalienne des Quentrix" stays whole.
  The dry-run must report the regex ORG TPs that change, because shorter spans can lose TPs where the GT includes lower-case words inside the name (Q4 descriptors).
- **R-SPLIT (spaCy, 3.3): line-break split.** Line breaks are one defined set, `LINE_BREAK` = {`\n`, `\r`, `\v`, `\f`, `\x85`, U+2028, U+2029}, the same characters `HSPACE` excludes (R-LB). The 10.2 C2 trim (`_trim_at_line_break`, `\n` only) is left as it is. Default: split at every `LINE_BREAK` character and keep each segment that holds an upper-case letter or a digit, as its own entity. Alternative to dry-run: keep only segments that hold a capitalised word that is not a label word. This covers "Cordialement,⏎⏎<Name>", "<Name>⏎<Heading>" and "PROCÈS-VERBAL …⏎<Org>". The default is coverage-preserving by construction; the alternative is not, so it would need the AC6 sign-off.
- **R-TS (TechSolutions @42, AC4).** It is expected to disappear once R-LB/R-ORG remove the run-on regex ORG that feeds the union. If it does not, dry-run the 10.2 handoff option: "no C2 trim when the cut-off tail holds a capitalised word not covered by another kept same-type span", which is the precise-guard logic applied to C2.
- **R-REL4 (AC5):** (a) keep the sentence-start exception; (b) drop it, so every capitalised word must be covered; (c) except only sentence-initial function words from a resource (articles, pronouns, conjunctions, common adverbs: "Le", "La", "Les", "Nous", "Il", "Elle", "Cette", "Ce", "Mais", "Et", "Donc", …, each with a `why`).
- **Hard-wrapped PDF lines (known risk, STOP R):** a name wrapped over two lines by PDF text extraction is no longer one span after R-LB/R-SPLIT. Not fixed in 10.3a; documented by a unit test and presented to Lionel.
